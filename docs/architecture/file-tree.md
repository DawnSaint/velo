# File Tree and Workspace

> **本文件负责**: 工作区模型、文件树懒加载、CRUD、右键菜单、内部拖拽 move、树刷新与相关踩坑。
>
> **何时阅读**: 改 `Sidebar/FileTree.vue`、`useTreeData.ts`、`useDragMove.ts`、`useInlineEdit.ts`、`useVirtualScroll.ts`、`useCopyPaste.ts`、`RootActionButtons.vue`、`workspaceStore`、文件树 CRUD / drag/drop / fs.watch 刷新时。
>
> **先记住**:
> - TreeNode 必须经 `reactive()` 包装，`dirIndex` 与 `rootNode` 必须持有同一份 proxy。
> - `loadDirChildren` 按 name + isDir 复用旧 TreeNode，避免整树闪烁。
> - 删除/重命名/移动当前打开文件必须走 `documentStore.loadContent` 既有契约，不要自起 watch。
> - 跨目录 move 成功后顺序是 renamePathPrefix → global recent rewrite → loadContent(必要时) → pruneDirIndexPrefix → 双侧刷新。
> - FileTreeContextMenu 只展示/emit，关闭与全局 pointerdown 由 useContextMenu composable 统一管。
>
> **相关文件**: [架构入口](../ARCHITECTURE.md) / [Tauri](./tauri.md) / [工作区搜索](./workspace-search.md)
>
> **文件树模块拆分结构**:
> - `FileTree.vue` — UI 状态机 + 事件接线 + 模板(目录展开 / 文件点击 / 右键菜单 / 删除 / revealFile / 全局监听 / 生命周期)
> - `useTreeData.ts` — 数据层:rootNode / dirIndex / loadDirChildren / refreshDir
> - `useDragMove.ts` — 拖拽源 + 内部 move( dragOverTarget / hover-expand / performMove)
> - `useInlineEdit.ts` — 行内编辑:新建 / 重命名状态机 + 校验 + 提交
> - `useVirtualScroll.ts` — 虚拟滚动 + Sticky 目录头(ROW_HEIGHT / visibleRange / stickyHeaders)
> - `useCopyPaste.ts` — 复制 / 粘贴(clipboard / copyDirRecursive / pasteInto)
> - `RootActionButtons.vue` — 根行四个操作按钮(新建 / 新建文件夹 / 刷新 / 全部折叠),消除普通行与 sticky 头的重复模板
> - `treeUtils.ts` — 纯函数:路径处理 / 排序 / 命名校验 / 错误格式
> - `FileTreeContextMenu.vue` — 右键菜单 UI
>
> composable 之间通过回调参数解耦(`closeContextMenu` / `cancelInline` 由 FileTree 传入),不直接互相引用。


## 禁令速查

- FileTree 新增节点不要 raw 对象，必须 `reactive()` 包。
- CRUD 后不要全量重建整树，要复用旧 TreeNode。
- CRUD 后 children 更新与 inline 关闭不要跨 await。
- 内部拖拽 move 不要两次 `loadContent`，不要保留旧路径 watch。
- 跨目录 move 后不要漏 `pruneDirIndexPrefix`。

## 数据流

**文件树 CRUD**(v0.5.1): `FileTree.vue` 右键菜单(由 `FileTreeContextMenu.vue` 抽组件)直走 `src/tauri/fs` 的 `mkdir` / `remove` / `rename` / `writeTextFile` + `src/tauri/opener:revealItemInDir`(plugin-shell 的 `open(path)` 不能"高亮文件",plugin-opener 专门补这条);新建 / 重命名走行内 input,`.md` 后缀不可编辑自动拼接;mutation 后立刻 `loadDirChildren(parent)` 主动重拉,不等 fs:watch 的 120ms debounce;`loadDirChildren` **按 name + isDir 复用旧 TreeNode 引用**,未变化的子树 props 不变,Vue 跳过;children 更新与行内编辑 / 打开文件关闭合并在同一 microtask 同步排列,Vue 一次 flush,避免两帧闪烁。**复制 / 粘贴**(v0.5.x):组件本地 `clipboard` ref 记源路径 + 是否目录(单实例剪贴板,不清,支持多次粘贴);文件走 `fs.copyFile`,目录走递归 `readDir` + **侧栏宽度(v0.5.5→v0.7.13 全局粒度)**:`workspaceStore.sidebarWidth` 是 computed 读 `editorStore.sidebarWidth`(全局 UI 偏好,走 `velo-settings.json`),不再 per-workspace 持久化。所有工作区/窗口共享一个宽度值(px,200-600,默认 256)。`workspaceStore.setSidebarWidth` 委托 `editorStore.setSidebarWidth`(clamp 在 editorStore 层)。App.vue 在 `useResizeSplitter` composable 的 clamp 双层防御。splitter 拖拽在 `useResizeSplitter.startDrag` 走 `mousedown` + window-level `mousemove/mouseup`(不用 HTML5 draggable,Tauri 即便 `dragDropEnabled: false` 仍会监听 dragenter/dragover 探测 OS 文件 drop)。splitter DOM 保留 4px 透明命中区,视觉分隔由 `::before` 画 10px 朝右渐变 shadow(从 splitter 左缘 / sidebar 右缘延伸到编辑器区内 6px,与功能区视觉相接无间隙);hover / dragging 时 `::after` 出现 3px 主题色硬线作拖拽抓取反馈(`::after` 画在 `::before` 之上确保盖在 shadow 渐变之上)。shadow 画在 splitter 而非编辑器区 `::before`,因编辑器区的 `overflow-hidden` 会裁剪负偏移 `::before` 导致 shadow 与功能区之间出现空隙;splitter 的 `z-index:1` 使 shadow 浮在编辑器内容(z-index:auto)之上,不被子组件不透明背景覆盖。窗口 innerWidth 低于阈值(SIDEBAR_WIDTH_MIN + ActivityBar 48 + 编辑器最小 360 = 608)时 `onCollapse` 把 `leftPanelView` 置 null,收起一次。窗口 resize 回上不自动展开(VSCode 风格,用户主动选择)。

**侧栏拖拽双阈值 + 死区 snap(v0.5.5 后期调整,VSCode / Obsidian 风格)**:`useResizeSplitter` 暴露 `dragCollapseBelow` + `onDragCollapse` + `onDragReopen` 三件套。**两个阈值**:A = `DRAG_COLLAPSE_BELOW`(80,左阈值,拖到此处及以下收起);B = `SIDEBAR_WIDTH_MIN`(200,右阈值,稳定下限)。三段语义:
- `[0, A)`:**drag-collapse 区**。`onCommit` 不写 store(瞬时值),`onDragCollapse` 把 `leftPanelView` 置 null,侧栏与 splitter 一起 `v-if` 消失。
- `[A, B]`:**死区**。`onCommit` 写 `B` 到 store;`displaySidebarWidth` 用 `Math.max(sidebarWidthRef, B)` 把视觉宽度强制 snap 到 `B`。**屏幕上看不到 [A, B] 之间的瞬时值** —— 这是用户报告的"拖到 75 release 后再从 100 开始拖,线在 75 位置开始动"的根因(之前死区内的 raw 值被 onCommit 挡住不写 store,导致 release 时 displaySidebarWidth 从 ref 切到 store 时瞬时跳变,且下一次 drag start 拿到的 dragStartWidth 与视觉宽度错位)。
- `(B, MAX]`:**稳定区**。`onCommit` 写 raw 到 store,视觉宽度 = raw。
用户拖回 `[A, MAX]` 时 `onDragReopen` 把侧栏按收起前的视图('sidebar')恢复,拖拽继续 —— 但死区内视觉停在 B,跨过 B 之后才跟手。App.vue 在 `onDragCollapse` 时把"当前 view" snapshot 到 `dragCollapseRestoreView` ref,`onDragReopen` 还原;`isDragging` watcher 在拖拽开始/结束两个方向都把 snapshot 清空,避免陈旧值误导下次普通点击。

**`setActiveRoot` 不强切 sidebarTab**:用户主动切工作区(顶栏"打开文件夹"按钮 / 二次启动 dir argv)保留当前 tab,只把当前 tab 写回新 workspace 记忆;**唯一**应用持久化 tab 的路径是 `loadFrom`(启动恢复)。否则"用户在文件 tab 时切工作区被强制弹回大纲"反直觉。sidebarWidth(v0.7.13)走全局粒度:切工作区时 sidebarWidth 保持当前值(所有工作区/窗口共享一个值),不再有 per-workspace READ/WRITE 语义。

**树右键"在新窗口中打开"走多窗口而非当前窗口切工作区**:右键子目录 → `newAppWindow({ dirs:[node.fullPath] })`,新窗口 onMounted 领到 payload 后路由 `setActiveRoot`,与当前窗口状态隔离(工作区 / 当前文档 / dirty prompt 按窗口隔离,见 `architecture/tauri.md`)。web 端(无 Tauri)降级为当前窗口内 `setActiveRoot`,与旧行为一致。

**工作区标签持久化(v0.6.0)**: `WorkspaceState` 加 `openTabs: string[]` + `activeTab?: string`(WORKSPACES_VERSION 3 → 4)。数据源是 `documentStore.openFilePaths`(computed,过滤未命名空白 / sample,保 documents 插入序),App.vue 在 setup 顶层挂 `watch([documentStore.openFilePaths, documentStore.currentFilePath], ...)` 调用 `workspaceStore.setOpenTabsForActiveWorkspace(...)` 写盘。已有 `workspaceStore.workspaces` 的 deep watch 自动触发 500ms `debouncedWorkspaceSave`,不开新 debouncer。**跨 root 过滤在 store 内部做**(用 `isPathInRoot`):用户从工作区 A 切到 B 时 watcher 不会污染 B 的 openTabs。**启动恢复**(App.vue onMounted 段,`shouldRestoreActive && !initialFile` 时):有持久化标签则跳过 `startupMode='last-file'` 单文件打开,走**两阶段恢复**:Phase 1 `createTabsFromPaths(persistedOpenTabs, persistedActiveTab)` 立即创建全部标签条目(只设 `currentFilePath` 供 TabBar 显示文件名,不读盘 / 不装载内容 / 不启 fs:watch)—— 用户先看到 Tab 标题;Phase 2 `loadContentIntoTabs(persistedOpenTabs, { silent: true })` fire-and-forget 并发读盘 + 同步 `loadContentInto` 装载内容(content / lastSavedContent / fs:watch / canonical markdownIO),内容稍后出现。`tabsReady` ref 在 Phase 1 后置 true,守门编辑器 / WelcomeDialog 不再闪“未命名” Tab。失败文件 silent 路径仅 console.warn,标签保留但 content 为空。无持久化标签时回退 `last-file` / `init('')` 单标签。App.vue setup **不再调** `init('')`(避免先显示“未命名” Tab),改由 onMounted 末尾 fallback 创建。**renamePathPrefix / removePathPrefix** 已扩展同时清洗 openTabs + activeTab;`documentStore.closeTabsUnderPath` / `renameOpenPaths` 不直接写 store,但 watcher 自动接它们的副作用。

## 设计要点

- **工作区根 fs.watch 走单 recursive 句柄 + 脏目录集 debounce**: `activeRoot` 变化时先 stop 后 start(沿用 documentStore 同款 race 容忍策略),回调把 `dirnameOf(event.paths)` 入 `dirtyDirs` Set,前端 120ms `setTimeout` 二次 debounce flush → 对每个脏目录调 `FileTree.refreshDir(dir)` 重拉那棵子树。`readDir` 一次 < 5ms,**不做 path diff**,简单可靠。当前文件 watch 与工作区根 watch 共存:当前文件也落在根树下会收到两份事件,documentStore 内 `disk === lastSavedContent` 短路 + `externalCheckInFlight` 重入保护已足够去重,不需要协调。**已知限制**:notify-rs 对网络盘 / OneDrive 漏报在目录级比文件级更严重,window-focus 兜底只覆盖当前文件,工作区根侧暂无等价兜底(代价高),见 DECISIONS ADR-20260623-001
- **ActivityBar 自定义持久化粒度(v0.6.1)**: 工作区/大纲/全局搜索/资产 4 个视图入口可拖拽重排(HTML5 `draggable`,对齐 TabBar;纵向列表 → 用 `clientY` 判 before/after,但落点统一规范化为「before 下一个」(仅末尾项退回 after),避免相邻图标缝隙出现两条 divider 扫过时抖动 —— 同 TabBar 范式)+ 4 项可隐藏(settings 固定不可隐藏;右键功能栏弹 `ActivityBarContextMenu` toggle + 重置默认)。布局是**全局 UI 偏好**,走 `editorStore` → `velo-settings.json`,**不**随工作区持久化 —— 与 `sidebarWidth` / `sidebarTab` 的 per-workspace 语义对照:功能栏布局跨工作区一致,不应每个工作区各存一份。`「文件」`(FileMenuButton)固定顶部、`「设置」`固定底部均不参与排序(`「文件」`拖拽会与 `#trigger` slot-ref 注册链冲突;`「设置」`沿用 VSCode「齿轮固定底部」约定);两者亦均不可隐藏(`「文件」`隐藏会孤立文件命令,`「设置」`固定显示)。隐藏当前 active 入口时 App.vue watcher 把 `leftPanelView` 置 null(避免「面板还开着但无 active 按钮」悬空态)。`ActivityBarContextMenu` 是勾选 toggle + 重置的纯展示,与右键动作菜单的「条件可见项」逻辑不重合,走 ContextMenuShell + useContextMenu 同一套基础设施。**active 左侧竖条指示器**:一根 2px 宽主题色竖条(`.activity-bar__accent`)贴 nav 左缘,根据 active 按钮的 DOM 位置算 `top`,CSS `transition` 驱动滑动(同 SettingsPage Tab 下划线滑动范式);active 项不再用 `background: color-mix(...)` 叠色,仅靠竖条 + 文字主色表达选中态,视觉更克制

**设置页(v0.7.x #settings-panel 重做)**: 设置从原工作区左侧栏(`leftPanelView === 'settings'` 的 ~256px 窄面板)改为**整页接管编辑器主区域**的 `SettingsPage.vue`。`LeftPanelView` 类型收窄为 `'sidebar' | null`(设置不再占用左侧栏);App.vue 新增 ## 维护者注意点

- **FileTree 的 TreeNode 必须 `reactive()` 包装**: `dirIndex: Map<string, TreeNode>` 与 `rootNode = ref<TreeNode>` 持有同一份引用,如果用 raw 对象,`rootNode.value = node` 后 ref 里是 proxy,Map 里是 raw,异步 `loadDirChildren` 对 raw 改 `node.loading=false / node.children=[...]` 不触发模板重渲 → UI 永远卡在"加载中…"且**控制台无报错**。`makeNode` 统一返回 `reactive({...})`,保证 dirIndex 与 rootNode 内全是 proxy
- **KeepAlive 下的 Sidebar 子组件必须按 activated/deactivated 管监听**: App shell 为了避免 Files 面板收起再展开时重建 FileTree,会缓存 `Sidebar` 实例;这不等于隐藏时还能保留全局副作用。`FileTree` 的 document 级 pointerdown / keydown / dragend 与 hover-expand timer,以及 `EditorOutline` 的 scroll-spy listener / rAF / 延迟 attach timer,都必须在 deactivated 时解绑或清掉,activated 再恢复。否则编辑器区域的点击或滚动会误触隐藏侧栏的行内编辑、菜单关闭或大纲高亮;反过来,不要把 `Sidebar.vue` 内部 files / outline 改成 `v-show`,两者仍要互斥卸载。
- **treeDrop / imageUploadPlugin 异步 drop 的 dropPos 越界 + race 守卫**:
    - `dropPos` 在落盘(含 `saveImageAssetFromPath` 磁盘读 + SHA-256 + 写,可达数秒)之前就已捕获,用户在此期间继续编辑导致 doc 变长/变短 → 原先的 pos 可能越界。`insertImageNode` 里做了 `Math.min(Math.max(dropPos, 0), doc.content.size)` clamp,**不 clmap 会 silent swallow RangeError → 图丢了用户无反馈**。
    - `.md drop → confirmDiscardIfDirty → openPath` 这条链如果等待对话框期间又来了一次图片 drop,那张图的 `dropPos` / `srcForMarkdown` 都是针对旧 doc 算的。`handleTreePathDrop` 产出的 `InsertImageFn` 签名带了 `capturedCurrentFilePath` 参数,`imageUploadPlugin` / `SourceModeEditor` 两侧在回调开头对比当前 `documentStore.currentFilePath` vs `captured`,不一致就跳过插入。**不跳则图插到新 doc 里 src 用了旧 assets/ 相对路径 → 图片裂开**。
- **行内 input 校验失败不要自动关闭**: v0.5.1 起新建 / 重命名不再走 modal,改行内 input(对齐 VSCode / Finder 约定)。Enter 提交、Esc 取消、点外部提交。submit 时跑 validate(空名 / `.` `..` / 禁用字符 / 同名),失败把 `inlineNew.error` / `inlineRename.error` 写进 input 的 `title` 属性,row 仍存在,焦点回 input。**空名校验必须落在 input value 上,不能在 finalName(已拼 `.md`)上** —— 空 + ".md" = ".md" 仍非空,会漏过 trim 后的检查。同名冲突这种"前端 children 视图可能不完整"的情况也只放在 submit 时校验,不在 typing 阶段报红字打扰用户。父目录若未展开,`openInlineNew` 须先 `setDirExpanded(true) + loadDirChildren`,否则 inline row 落到不可见的折叠子树
- **重命名 / 删除当前打开文件 → 走 `documentStore` 既有契约,不要在 FileTree 内自起 watch**:
    - 删除:`deleteContainsOpenFile(pathToDelete)` 判 `currentFilePath === pathToDelete || currentFilePath.startsWith(pathToDelete + sep())`,命中就 `loadContent('', null)` 让 documentStore 走自己的 stopWatch + 清 currentFilePath 路径(等价"用户从 OS 删了再打开")
    - 重命名:`currentFilePath === node.fullPath` 时调 `loadContent(documentStore.content, newPath)` —— 不动 content / lastSavedContent,只换 path + 内部 stopWatch + startWatchOf(newPath)(等价 `saveAs` 的 watch 切换路径)。**不要**自己 dispatch watch / 自己 mutate currentFilePath,store 内部 `loadContent` 才同步触发 stopWatch / startWatchOf + syncTitle,漏走一条 watch 路径都会让外部修改检测漂到旧路径上,文件重命名后再编辑 = checkExternalChange 拿旧路径读文件找不到
- **Tauri 2 plugin-opener 只能 desktop**: `revealItemInDir` 移动端 unsupported,Velo 当前只打 desktop,future 加 mobile entry 时需自行在 capability / 调用点降级(消息弹"不支持")
**侧栏宽度持久化粒度(v0.5.5→v0.7.13 全局粒度)**:`sidebarWidth` v0.5.5 走 per-workspace 持久化(字段加在 `WorkspaceState` 上);v0.7.13 迁到全局 `PersistedSettings.editor.sidebarWidth`(走 `velo-settings.json`),所有工作区/窗口共享一个值。常量 `SIDEBAR_WIDTH_MIN`/`MAX`/`DEFAULT` + `clampSidebarWidth` 的 canonical home 从 `workspace.ts` 迁到 `editor.ts`,`workspace.ts` re-export 保持 App.vue / composable 的 import 路径不变。`workspaceStore.sidebarWidth` 改为 computed 读 `editorStore.sidebarWidth`;`workspaceStore.setSidebarWidth` 委托 `editorStore.setSidebarWidth`。`WORKSPACES_VERSION` bump 到 5;`WorkspaceState.sidebarWidth` 字段已从接口删除,旧 JSON 中的 per-workspace `sidebarWidth` 由启动期 `migrateWorkspacesIfNeeded` 迁移到 `velo-settings.json`(全局值优先——settings 文件已有 `sidebarWidth` 时不覆盖),迁移后从 workspaces JSON 中删除该字段。store + composable 双层 clamp(SIDEBAR_WIDTH_MIN=200 / SIDEBAR_WIDTH_MAX=600),常量从 `@/stores/workspace` named export 共享(实际从 `@/stores/editor` re-export),UI 层(侧栏子组件)只设 `min-w-0` 允许 splitter 拉到 200px,**不再**用 `min-w-64` 卡死下限。**死区 snap(v0.5.5 后期调整)**:A = DRAG_COLLAPSE_BELOW(80,左阈值,collapse),B = SIDEBAR_WIDTH_MIN(200,右阈值,稳定下限)。`[A, B]` 死区视觉宽度 snap 到 B(由 App.vue 的 `displaySidebarWidth = Math.max(sidebarWidthRef, B)` + `onCommit` 写 B 协同保证),屏幕上根本看不到 80-200 之间的瞬时值,避免 release 后"线从中间位置开始动"的视觉错位
- **拖拽用 mouse 事件不用 draggable(v0.5.5)**: `useResizeSplitter` 走 `mousedown` + window-level `mousemove/mouseup`,**不**用 HTML5 `draggable`。原因:Tauri 即便 `dragDropEnabled: false` 仍会在底层监听 `dragenter` / `dragover` 探测 OS 文件 drop,启用 `draggable` 后 splitter 的 drag 会被错误识别,可能触发 ImageUploadPlugin 的 drop handler 或与文件树拖拽语义混淆(详见 memory: `tauri-2-dragdropenabled-default`)。mouse 事件路径完全不被 Tauri 截获,安全
- **拖拽中 `<aside>` 加 `pointer-events: none` 防根行按钮 / scrollbar 闪烁**: splitter 拖拽宽度走 rAF 节流,视觉宽度比鼠标位置滞后最多 1 帧(~16ms)。这个滞后窗口内鼠标可能短暂进入侧栏区域触发 `mouseenter` → 下一帧 splitter 追上鼠标又触发 `mouseleave`,反复交替导致 FileTree 根行四个按钮(`workspaceHovered` 控制 opacity)和浮动滚动条 thumb(`v-velo-scroll` 指令的 `mouseenter`/`mouseleave` 控制 `velo-scroll-thumb-visible` class)快速淡入淡出 = 闪烁。修复:App.vue 的 `<aside>` 在 `sidebarSplitter.isDragging.value` 为 true 时加 `pointer-events-none` class,阻止侧栏内所有子元素接收鼠标事件,冻结 hover 状态。拖拽结束后移除,恢复正常 hover 行为
- **拖拽中冻结 `.velo-editor` 宽度防大文档卡顿(v0.7.8)**: splitter 拖拽每帧(rAF)更新 aside 宽度 → flex 布局重算编辑器区域 → `.velo-editor` 宽度变化(当可用空间 < 64vw 时)→ 大文档所有可见段落 text reflow + `content-visibility:auto` 子元素 intersection 重算 + `ResizeObserver` 回调(`tableInsertHandle.repositionDots` / `veloScroll.updateThumb`)调 `getBoundingClientRect()` 强制同步 layout flush → 每帧 > 16ms → 卡顿。修复:App.vue 的 `isDragging` watcher 在拖拽开始时测量 `.velo-editor` 当前像素宽度,设到 `--velo-drag-editor-width` CSS 变量 + 加 `body.velo-dragging-sidebar` class;`index.scss` 的 `body.velo-dragging-sidebar .velo-editor` 规则用固定宽度覆盖 `w-full` + `max-w-[64vw]` + `flex-shrink:0`,阻止 text reflow。拖拽结束后 JS 移除 class + 变量,编辑器宽度一次性适配新容器(单次 reflow 可接受)。**源码模式(CM6)不需要此优化**:CM6 用虚拟化渲染(只渲染可见行),宽度变化时 reflow 成本极低
- **drag-reopen snapshot 必须在拖拽两端都清(v0.5.5)**: `onDragCollapse` 触发时 App.vue 把当前 `leftPanelView` 存到 `dragCollapseRestoreView`,`onDragReopen` 用它还原。**关键**:`isDragging` watcher 在 `false→true`(新拖拽开始)和 `true→false`(拖拽结束)两拍都把 snapshot 置 null —— 因为拖拽过程中用户可能 release 鼠标在 collapse 区(没回到阈值之上),此时 snapshot 仍持有 'sidebar'。如果只清结束不重新开始,下一次新拖拽从"未拖过的状态"起,理论上没问题;但只有"开始清空"才能保证"`wasDragCollapsed` reset"和"snapshot reset"同步,避免 onDragCollapse 第一次 fire 时误读陈旧 snapshot;而"结束清空"则保护普通交互(用户 release 后用 ActivityBar 切别的 tab)时,陈旧 snapshot 不会在某个边角路径上重新打开不该开的东西
- **编辑器侧 flex `min-w-0` 链必须完整**: 侧栏开合时编辑器要被「压缩」(宽度收缩、内容 reflow)而非被「推动」(宽度不变、右侧溢出被 `overflow-hidden` 裁剪)。flex item 默认 `min-width: auto` = `min-content`,编辑器有宽内容(表格 / 长 code block)时 `min-content` 很大,flex item 无法收缩 → 侧栏把编辑器整体推右,右侧内容不可见。`min-w-0` 链从 App.vue 编辑器区域(`flex flex-1 flex-col min-w-0`)起,经内层 flex-row(`flex flex-1 overflow-hidden`,overflow 使自动 min-width=0),到 `ProseMirrorEditor/index.vue` 根 div(`relative flex-1 min-w-0`)、`velo-editor` 内容 div(`h-full w-full min-w-0 max-w-[64vw]`)、`SourceModeEditor.vue` 根 div(`velo-cm-source relative flex-1 min-w-0`)、App.vue 空态 div(`flex flex-1 min-w-0 flex-col`)。**任何一层漏 `min-w-0` 都会让宽内容撑住整条链,侧栏开合变成「推」而非「压」**
