# File Tree and Workspace

> **本文件负责**: 工作区模型、文件树懒加载、CRUD、右键菜单、内部拖拽 move、树刷新与相关踩坑。
>
> **何时阅读**: 改 `Sidebar/FileTree.vue`、`useTreeData.ts`、`workspaceStore`、文件树 CRUD / drag/drop / fs.watch 刷新时。
>
> **先记住**:
> - TreeNode 必须经 `reactive()` 包装，`dirIndex` 与 `rootNode` 必须持有同一份 proxy。
> - `loadDirChildren` 按 name + isDir 复用旧 TreeNode，避免整树闪烁。
> - 删除/重命名/移动当前打开文件必须走 `documentStore.loadContent` 既有契约，不要自起 watch。
> - 跨目录 move 成功后顺序是 renamePathPrefix → global recent rewrite → loadContent(必要时) → pruneDirIndexPrefix → 双侧刷新。
> - FileTreeContextMenu 只展示/emit，关闭与全局 pointerdown 由父级统一管理。
>
> **相关文件**: [架构入口](../ARCHITECTURE.md) / [Tauri](./tauri.md) / [工作区搜索](./workspace-search.md)


## 禁令速查

- FileTree 新增节点不要 raw 对象，必须 `reactive()` 包。
- CRUD 后不要全量重建整树，要复用旧 TreeNode。
- CRUD 后 children 更新与 inline 关闭不要跨 await。
- 内部拖拽 move 不要两次 `loadContent`，不要保留旧路径 watch。
- 跨目录 move 后不要漏 `pruneDirIndexPrefix`。

## 数据流

**文件树 CRUD**(v0.5.1): `FileTree.vue` 右键菜单(由 `FileTreeContextMenu.vue` 抽组件)直走 `src/tauri/fs` 的 `mkdir` / `remove` / `rename` / `writeTextFile` + `src/tauri/opener:revealItemInDir`(plugin-shell 的 `open(path)` 不能"高亮文件",plugin-opener 专门补这条);新建 / 重命名走行内 input,`.md` 后缀不可编辑自动拼接;mutation 后立刻 `loadDirChildren(parent)` 主动重拉,不等 fs:watch 的 120ms debounce;`loadDirChildren` **按 name + isDir 复用旧 TreeNode 引用**,未变化的子树 props 不变,Vue 跳过;children 更新与行内编辑 / 打开文件关闭合并在同一 microtask 同步排列,Vue 一次 flush,避免两帧闪烁。**复制 / 粘贴**(v0.5.x):组件本地 `clipboard` ref 记源路径 + 是否目录(单实例剪贴板,不清,支持多次粘贴);文件走 `fs.copyFile`,目录走递归 `readDir` + `mkdir` + `copyFile`;`treeUtils.uniqueName` 处理同名冲突(`foo 副本.md` / `foo 副本 2.md`);目录禁止贴入自身后代(同 move 的 ancestor 守卫);成功后刷新目标目录 children。**联动 `documentStore`**:删除影响"当前打开文件"(含落在被删子树里的情况)→ `loadContent('', null)` 关闭文件,内容丢;重命名"当前打开文件"→ 走 ROADMAP line 19 同款"路径同步更新 currentFilePath 不重载内容"语义,通过 `documentStore.loadContent(content, newPath)` 复用 stopWatch + startWatchOf 路径,destructive op(destructive op 必 confirm,删除 dirty 文件文案加"未保存修改将丢失")在 FileTree 内弹原生 confirm。**最近文件同步**:重命名 / 内部 move 成功后同时重写 workspace recent 与全局 recent 的旧路径前缀;删除成功后移除对应前缀,避免 Ctrl+P 最近段或顶栏最近文件指向死路径。**内部拖拽 move**:文件走 TREE_PATH_MIME,**目录走 TREE_DIR_PATH_MIME**(独立 MIME 让目录无法被拖入编辑器,详见 imageUploadPlugin 行);FileTree 内部 drop 两种 MIME 都接受走 `fs.rename`(对 file/dir 同管线);校验链 src===dst / parent(src)===dst / 目录拖入自身后代;成功后 `fs.rename` → `workspace.renamePathPrefix(srcPath, newPath)` 把 expandedDirs / lastFile 前缀重写 → `recentFiles.renamePathPrefix(srcPath, newPath)` 重写全局最近文件 → `loadContent(content, newPath)` 多标签联动(v0.6.0)**: `onFileClick` 走 `openPathInTab`(已开则切到该标签,未开则新开);中键点击 `@auxclick.middle.prevent` 走 `onRowAuxClick` → `openPathInNewTab`(始终新开,VSCode 资源管理器中键语义,允许同文件并存于多个标签,各自独立 undo / 滚动 / 光标)。目录 / 图片 / 根行 no-op;两条路径都调 `workspace.setLastFile`,工作区重开恢复最近文件不区分开标签方式。**右键菜单「在此文件夹中搜索」(v0.6.0)**: `FileTreeContextMenu` 在「在新窗口中打开」之后新增一项,仅 `!rootContext && isDir` 时显示 —— 根目录 / 根上下文 / 文件节点均不暴露。emit `search-in-folder` 给 `FileTree.vue`,后者再 emit 给 `Sidebar.vue` → App.vue → 切到 search tab 并把目录路径写入 `workspaceSearchScopeDir` ref(FileTree 不持有搜索状态,App.vue 的 ref 是单一来源,避免两处镜像)。入口语义对齐 VSCode「Find in Folder...」:在工作区子目录里快速定位,不必切换工作区根。scope 显示在搜索面板 header 的 chip 中(带 ✕ 清除),点 × 回退到工作区根。
**工作区**: `workspaceStore.activeRoot` 是当前 WebView/window 的 runtime 状态;多窗口下每个 Velo 窗口各自持有 activeRoot / 当前文件 / dirty。`workspaces[root].{expandedDirs,lastFile,sidebarTab,sidebarWidth,recentFiles}` 是全局共享的 per-root 记忆,落到 `velo-workspaces.json`;保存走当前窗口 active root patch merge,避免窗口 A 的旧全量快照覆盖窗口 B 新打开的 workspace。`velo-workspaces.json.active` 仅作为 main 窗口冷启动恢复 hint,动态窗口不会继承它。App shell v0.6.x 顶层布局改为 `flex-row` 三列:[ActivityBar | 左侧功能区 | 右侧列(顶栏 + 编辑器)]。ActivityBar 与左侧功能区均从 y=0 起到 StatusBar 上沿接顶,Velo logo 已移除;「文件」命令入口、原 `RecentFilesButton` 与开发模式欢迎按钮统一收纳进 ActivityBar 第一个位置(由 `FileMenuButton` 提供下拉面板,ActivityBar 通过 `#trigger` 插槽提供 ActivityBar-styled 触发按钮)。Outline 仍与 Files 共用 `Sidebar.vue`,实际 tab 语义由 `workspaceStore.sidebarTab` 承担,ActivityBar 只负责面板显隐与入口事件。App shell 用 `KeepAlive` 保留 `Sidebar` 实例,避免 ActivityBar 收起 / settings 切换 / auto-collapse 后重新展开 Files 时销毁 FileTree 并重建根树;但 `Sidebar.vue` 内部仍走 tab 互斥渲染(v-if 而非 v-show),免得 EditorOutline scroll-spy DOM 监听与 FileTree dirIndex 同时活着争 scroll container。工作区根挂单 recursive `fs.watch`(delayMs:150 + 前端 120ms 二次防抖,脏目录集驱动 `FileTree.refreshDir` 子树重拉;Sidebar 暂不可用时 pending 到重新激活 Files 后刷新)。`documentStore.currentFilePath` 变化同步到 `workspaceStore.lastFile`,重开工作区时可恢复。

**侧栏宽度(v0.5.5)**:`workspaceStore.sidebarWidth` 是 top-level 镜像 ref,持久化落到 `activeWorkspace.sidebarWidth`(px,200-600,默认 256)。与 `sidebarTab` 同款 per-workspace 持久化语义,App.vue 在 `setActiveRoot` 里把新 workspace 的 width 同步到 top-level。`setSidebarWidth` 在 store 层 clamp(防止 UI 层 bug 直接写超界值);App.vue 还跑 `useResizeSplitter` composable 的 clamp(双层防御)。splitter 拖拽在 `useResizeSplitter.startDrag` 走 `mousedown` + window-level `mousemove/mouseup`(不用 HTML5 draggable,Tauri 即便 `dragDropEnabled: false` 仍会监听 dragenter/dragover 探测 OS 文件 drop)。splitter DOM 保留 4px 透明命中区,视觉线由左贴边 1px `::before` 承担;hover / dragging 时向左右各扩 1px 变 3px 主题色线,其中左侧 1px 覆盖侧栏边缘,避免命中区居中画线造成的透明缝。窗口 innerWidth 低于阈值(SIDEBAR_WIDTH_MIN + ActivityBar 48 + 编辑器最小 360 = 608)时 `onCollapse` 把 `leftPanelView` 置 null,收起一次。窗口 resize 回上不自动展开(VSCode 风格,用户主动选择)。

**侧栏拖拽双阈值 + 死区 snap(v0.5.5 后期调整,VSCode / Obsidian 风格)**:`useResizeSplitter` 暴露 `dragCollapseBelow` + `onDragCollapse` + `onDragReopen` 三件套。**两个阈值**:A = `DRAG_COLLAPSE_BELOW`(80,左阈值,拖到此处及以下收起);B = `SIDEBAR_WIDTH_MIN`(200,右阈值,稳定下限)。三段语义:
- `[0, A)`:**drag-collapse 区**。`onCommit` 不写 store(瞬时值),`onDragCollapse` 把 `leftPanelView` 置 null,侧栏与 splitter 一起 `v-if` 消失。
- `[A, B]`:**死区**。`onCommit` 写 `B` 到 store;`displaySidebarWidth` 用 `Math.max(sidebarWidthRef, B)` 把视觉宽度强制 snap 到 `B`。**屏幕上看不到 [A, B] 之间的瞬时值** —— 这是用户报告的"拖到 75 release 后再从 100 开始拖,线在 75 位置开始动"的根因(之前死区内的 raw 值被 onCommit 挡住不写 store,导致 release 时 displaySidebarWidth 从 ref 切到 store 时瞬时跳变,且下一次 drag start 拿到的 dragStartWidth 与视觉宽度错位)。
- `(B, MAX]`:**稳定区**。`onCommit` 写 raw 到 store,视觉宽度 = raw。
用户拖回 `[A, MAX]` 时 `onDragReopen` 把侧栏按收起前的视图('sidebar' / 'settings')恢复,拖拽继续 —— 但死区内视觉停在 B,跨过 B 之后才跟手。App.vue 在 `onDragCollapse` 时把"当前 view" snapshot 到 `dragCollapseRestoreView` ref,`onDragReopen` 还原;`isDragging` watcher 在拖拽开始/结束两个方向都把 snapshot 清空,避免陈旧值误导下次普通点击。

**`setActiveRoot` 不强切 sidebarTab**:用户主动切工作区(顶栏"打开文件夹"按钮 / 二次启动 dir argv)保留当前 tab,只把当前 tab 写回新 workspace 记忆;**唯一**应用持久化 tab 的路径是 `loadFrom`(启动恢复)。否则"用户在文件 tab 时切工作区被强制弹回大纲"反直觉。sidebarWidth(v0.5.5)反过来走 READ 语义:切到新 workspace 时**读**它的 sidebarWidth 到 top-level,而不是把当前 top-level 写过去。原因是 per-workspace 持久化要求各 workspace 保留自己的宽度,WRITE 语义会让"切回 /a 后宽度变成 /b 的"破坏 round-trip。新 workspace 走默认 256,符合"无偏好就用默认"。

**树右键"在新窗口中打开"走多窗口而非当前窗口切工作区**:右键子目录 → `newAppWindow({ dirs:[node.fullPath] })`,新窗口 onMounted 领到 payload 后路由 `setActiveRoot`,与当前窗口状态隔离(工作区 / 当前文档 / dirty prompt 按窗口隔离,见 `architecture/tauri.md`)。web 端(无 Tauri)降级为当前窗口内 `setActiveRoot`,与旧行为一致。

**工作区标签持久化(v0.6.0)**: `WorkspaceState` 加 `openTabs: string[]` + `activeTab?: string`(WORKSPACES_VERSION 3 → 4)。数据源是 `documentStore.openFilePaths`(computed,过滤未命名空白 / sample,保 documents 插入序),App.vue 在 setup 顶层挂 `watch([documentStore.openFilePaths, documentStore.currentFilePath], ...)` 调用 `workspaceStore.setOpenTabsForActiveWorkspace(...)` 写盘。已有 `workspaceStore.workspaces` 的 deep watch 自动触发 500ms `debouncedWorkspaceSave`,不开新 debouncer。**跨 root 过滤在 store 内部做**(用 `isPathInRoot`):用户从工作区 A 切到 B 时 watcher 不会污染 B 的 openTabs。**启动恢复**(App.vue onMounted 段,在 CLI 打开文件 + recent-file 兜底之后,`shouldRestoreActive && !initialFile` 时):调 `documentStore.openPathsInTabs(persistedOpenTabs, { silent: true })` —— IO 阶段 `Promise.all` 并发 readTextFile,commit 阶段同步批量装载到 store,TabBar 一次性拿到全部 N 个标签(不"一个个出现");失败文件 silent 路径仅 console.warn 不弹原生错误框;返回成功 path 列表后用 `findTabByPath` + `switchTab` 切到 `activeTab`,缺失则回退最后一个装载成功的标签。**renamePathPrefix / removePathPrefix** 已扩展同时清洗 openTabs + activeTab;`documentStore.closeTabsUnderPath` / `renameOpenPaths` 不直接写 store,但 watcher 自动接它们的副作用。

## 设计要点

- **工作区根 fs.watch 走单 recursive 句柄 + 脏目录集 debounce**: `activeRoot` 变化时先 stop 后 start(沿用 documentStore 同款 race 容忍策略),回调把 `dirnameOf(event.paths)` 入 `dirtyDirs` Set,前端 120ms `setTimeout` 二次 debounce flush → 对每个脏目录调 `FileTree.refreshDir(dir)` 重拉那棵子树。`readDir` 一次 < 5ms,**不做 path diff**,简单可靠。当前文件 watch 与工作区根 watch 共存:当前文件也落在根树下会收到两份事件,documentStore 内 `disk === lastSavedContent` 短路 + `externalCheckInFlight` 重入保护已足够去重,不需要协调。**已知限制**:notify-rs 对网络盘 / OneDrive 漏报在目录级比文件级更严重,window-focus 兜底只覆盖当前文件,工作区根侧暂无等价兜底(代价高),见 DECISIONS ADR-20260623-001

## 维护者注意点

- **FileTree 的 TreeNode 必须 `reactive()` 包装**: `dirIndex: Map<string, TreeNode>` 与 `rootNode = ref<TreeNode>` 持有同一份引用,如果用 raw 对象,`rootNode.value = node` 后 ref 里是 proxy,Map 里是 raw,异步 `loadDirChildren` 对 raw 改 `node.loading=false / node.children=[...]` 不触发模板重渲 → UI 永远卡在"加载中…"且**控制台无报错**。`makeNode` 统一返回 `reactive({...})`,保证 dirIndex 与 rootNode 内全是 proxy
- **KeepAlive 下的 Sidebar 子组件必须按 activated/deactivated 管监听**: App shell 为了避免 Files 面板收起再展开时重建 FileTree,会缓存 `Sidebar` 实例;这不等于隐藏时还能保留全局副作用。`FileTree` 的 document 级 pointerdown / keydown / dragend 与 hover-expand timer,以及 `EditorOutline` 的 scroll-spy listener / rAF / 延迟 attach timer,都必须在 deactivated 时解绑或清掉,activated 再恢复。否则 settings / 编辑器区域的点击或滚动会误触隐藏侧栏的行内编辑、菜单关闭或大纲高亮;反过来,不要把 `Sidebar.vue` 内部 files / outline 改成 `v-show`,两者仍要互斥卸载。
- **treeDrop / imageUploadPlugin 异步 drop 的 dropPos 越界 + race 守卫**:
    - `dropPos` 在落盘(含 `saveImageAssetFromPath` 磁盘读 + SHA-256 + 写,可达数秒)之前就已捕获,用户在此期间继续编辑导致 doc 变长/变短 → 原先的 pos 可能越界。`insertImageNode` 里做了 `Math.min(Math.max(dropPos, 0), doc.content.size)` clamp,**不 clmap 会 silent swallow RangeError → 图丢了用户无反馈**。
    - `.md drop → confirmDiscardIfDirty → openPath` 这条链如果等待对话框期间又来了一次图片 drop,那张图的 `dropPos` / `srcForMarkdown` 都是针对旧 doc 算的。`handleTreePathDrop` 产出的 `InsertImageFn` 签名带了 `capturedCurrentFilePath` 参数,`imageUploadPlugin` / `SourceModeEditor` 两侧在回调开头对比当前 `documentStore.currentFilePath` vs `captured`,不一致就跳过插入。**不跳则图插到新 doc 里 src 用了旧 assets/ 相对路径 → 图片裂开**。
- **行内 input 校验失败不要自动关闭**: v0.5.1 起新建 / 重命名不再走 modal,改行内 input(对齐 VSCode / Finder 约定)。Enter 提交、Esc 取消、点外部提交。submit 时跑 validate(空名 / `.` `..` / 禁用字符 / 同名),失败把 `inlineNew.error` / `inlineRename.error` 写进 input 的 `title` 属性,row 仍存在,焦点回 input。**空名校验必须落在 input value 上,不能在 finalName(已拼 `.md`)上** —— 空 + ".md" = ".md" 仍非空,会漏过 trim 后的检查。同名冲突这种"前端 children 视图可能不完整"的情况也只放在 submit 时校验,不在 typing 阶段报红字打扰用户。父目录若未展开,`openInlineNew` 须先 `setDirExpanded(true) + loadDirChildren`,否则 inline row 落到不可见的折叠子树
- **重命名 / 删除当前打开文件 → 走 `documentStore` 既有契约,不要在 FileTree 内自起 watch**:
    - 删除:`deleteContainsOpenFile(pathToDelete)` 判 `currentFilePath === pathToDelete || currentFilePath.startsWith(pathToDelete + sep())`,命中就 `loadContent('', null)` 让 documentStore 走自己的 stopWatch + 清 currentFilePath 路径(等价"用户从 OS 删了再打开")
    - 重命名:`currentFilePath === node.fullPath` 时调 `loadContent(documentStore.content, newPath)` —— 不动 content / lastSavedContent,只换 path + 内部 stopWatch + startWatchOf(newPath)(等价 `saveAs` 的 watch 切换路径)。**不要**自己 dispatch watch / 自己 mutate currentFilePath,store 内部 `loadContent` 才同步触发 stopWatch / startWatchOf + syncTitle,漏走一条 watch 路径都会让外部修改检测漂到旧路径上,文件重命名后再编辑 = checkExternalChange 拿旧路径读文件找不到
- **Tauri 2 plugin-opener 只能 desktop**: `revealItemInDir` 移动端 unsupported,Velo 当前只打 desktop,future 加 mobile entry 时需自行在 capability / 调用点降级(消息弹"不支持")
- **侧栏宽度持久化粒度(v0.5.5)**:`sidebarWidth` 走 per-workspace 持久化(与 `sidebarTab` 同 schema 形态),字段加在 `WorkspaceState` 上并随 `WORKSPACES_VERSION` bump 到 2。`loadWorkspaces` 同时接受 v1(无该字段,运行时兜底 256)和 v2,旧 JSON 无需手动迁移。store + composable 双层 clamp(SIDEBAR_WIDTH_MIN=200 / SIDEBAR_WIDTH_MAX=600),常量从 `@/stores/workspace` named export 共享,UI 层(侧栏子组件)只设 `min-w-0` 允许 splitter 拉到 200px,**不再**用 `min-w-64` 卡死下限——这是 ROADMAP 「大纲/文件侧边栏可拉伸」的最终落地形态。**死区 snap(v0.5.5 后期调整)**:A = DRAG_COLLAPSE_BELOW(80,左阈值,collapse),B = SIDEBAR_WIDTH_MIN(200,右阈值,稳定下限)。`[A, B]` 死区视觉宽度 snap 到 B(由 App.vue 的 `displaySidebarWidth = Math.max(sidebarWidthRef, B)` + `onCommit` 写 B 协同保证),屏幕上根本看不到 80-200 之间的瞬时值,避免 release 后"线从中间位置开始动"的视觉错位
- **拖拽用 mouse 事件不用 draggable(v0.5.5)**: `useResizeSplitter` 走 `mousedown` + window-level `mousemove/mouseup`,**不**用 HTML5 `draggable`。原因:Tauri 即便 `dragDropEnabled: false` 仍会在底层监听 `dragenter` / `dragover` 探测 OS 文件 drop,启用 `draggable` 后 splitter 的 drag 会被错误识别,可能触发 ImageUploadPlugin 的 drop handler 或与文件树拖拽语义混淆(详见 memory: `tauri-2-dragdropenabled-default`)。mouse 事件路径完全不被 Tauri 截获,安全
- **drag-reopen snapshot 必须在拖拽两端都清(v0.5.5)**: `onDragCollapse` 触发时 App.vue 把当前 `leftPanelView` 存到 `dragCollapseRestoreView`,`onDragReopen` 用它还原。**关键**:`isDragging` watcher 在 `false→true`(新拖拽开始)和 `true→false`(拖拽结束)两拍都把 snapshot 置 null —— 因为拖拽过程中用户可能 release 鼠标在 collapse 区(没回到阈值之上),此时 snapshot 仍持有 'sidebar' / 'settings'。如果只清结束不重新开始,下一次新拖拽从"未拖过的状态"起,理论上没问题;但只有"开始清空"才能保证"`wasDragCollapsed` reset"和"snapshot reset"同步,避免 onDragCollapse 第一次 fire 时误读陈旧 snapshot;而"结束清空"则保护普通交互(用户 release 后用 ActivityBar 切别的 tab)时,陈旧 snapshot 不会在某个边角路径上重新打开不该开的东西
- **FileTree 节点复用 + mutation 后立即清 inline 状态,避免整树闪烁**: v0.5.1 起 CRUD 写盘后,`loadDirChildren` **必须**按 name + isDir 复用旧 `TreeNode` 引用,只对新增 / 删除的 entry 建新对象。否则父级 `flatItems` computed 看到新 proxy 引用就 reconcile 整树 → 整树重渲闪烁;复用后未变化的子树 props 不变,Vue 跳过。`submitInline` / `confirmAndDelete` 中 `loadDirChildren` 与 `cancelInline` / `loadContent('', null)` 之间**不能有 await**(会跨 microtask 边界,Vue 分两帧 flush),必须同一 microtask 同步排列,Vue 一次 flush 渲染。`loadDirChildren` 内部 `node.loading` 切换在子目录不可见(只有根 root 触发"加载中…"),所以根的 loading 由 `rebuildFromRoot` 单独 toggle,`loadDirChildren` 不再 toggle,免得在没必要的子树触发 2 次额外 reactive 通知
- **FileTreeContextMenu 抽组件 + rootEl expose**: 右键菜单 5 项固定 UI + 5 个 emit,跟 FileTree 状态机耦合很浅,内联在 FileTree 会撑长模板。`FileTreeContextMenu.vue` 自管 `<Teleport to="body">` 并 `defineExpose({ rootEl })` 暴露 Teleport 后的 DOM 节点;FileTree 全局 `pointerdown` handler 拿 `contextMenuRef.value?.rootEl` 判定"点外部"关闭。**不**在组件内自己挂全局 listener(会和 FileTree 的 inline input close 逻辑竞争),也不在组件 emit close(让父级统一管理 `contextMenu.value` 状态)
- **同一范式扩展到 TabContextMenu.vue**: 标签条右键菜单(v0.6.x)沿用同款 Teleport + rootEl expose + 父级挂全局 listener 的范式;TabBar 而不是 App.vue 直接持有 sidebarRef,所以「在文件树中显示」通过 emit 上去由 App.vue 拼装 setSidebarTab('files') + sidebarRef.revealFile(path)。**不抽通用 ContextMenu 组件**:两份菜单的"是否显示某项"逻辑(按 isDir / filePath / activeRoot / dirty 等)互不相同,抽到数据驱动的 items + slot 会把判断散到调用方,得不偿失;后续若第三份菜单出现再合并
- **FileTree 内部拖拽 move:状态前缀重写 + dirIndex prune + 单次 loadContent**:
    - 与重命名 / 删除一样走 `documentStore.loadContent(content, newPath)` 既有契约,**不**自起 watch / 手动 mutate currentFilePath。dir 移动并包含当前文件时,直接合成 `newCur = newPath + cur.slice(srcPath.length)` 一次性传入,**不要**先 loadContent(content, srcPath) 再切到 newCur —— 两次 startWatchOf 会留一个指向已不存在路径的 watch 窗口。
    - `workspaceStore.renamePathPrefix(oldPath, newPath)` 必须早于 loadContent,把 `expandedDirs` / `lastFile` 中以 oldPath 为前缀的项整体重写;否则下次重开工作区 isDirExpanded 命中旧路径,readDir 抛错,整树降级到只展开根。
    - `pruneDirIndexPrefix(srcPath)` 必须紧跟 rename 成功:被移走的目录子树在 dirIndex 里全是孤儿(rootNode 已找不到它们,但 dirIndex 持有 key),后续工作区 fs.watch 用旧路径 debounced 调 `refreshDir` 会撞到孤儿,`readDir(deadPath)` reject 写 `node.error` 污染脱链节点。
    - 同 microtask 收尾(参考“FileTree 节点复用 + mutation 后立即清 inline 状态”):`fs.rename` resolve 之后 → renamePathPrefix → loadContent(必要时)→ pruneDirIndexPrefix → `Promise.all([loadDirChildren(srcParent), loadDirChildren(dstDir)])` 全程无 await 间隔,Vue 单帧 flush。
- **根节点纳入 flatItems + 1 级"空目录"探测**: v0.5.1 起根节点作为 `flatItems` 第一行渲染(`depth=0`),不再用顶部独立 label 显示。右键根 row 走 rootContext 上下文菜单(同空白处右键),仅显示"新建文件 / 新建文件夹",其余项(重命名 / 删除 / reveal / 在新窗口中打开)对根无意义。
    - **根折叠态走组件本地 `rootCollapsed` ref,不持久化**:折叠是临时 UI 操作,切工作区 / 重启都视觉默认展开。切工作区的 watch 必须显式重置 `rootCollapsed.value = false` —— FileTree 组件不会 unmount/remount,不重置会从上个工作区继承折叠态。不走 `workspace.expandedDirs` 是为了避开两个问题:一是污染"per-path 展开集"语义,二是要为旧 v0.5.0 工作区记忆做兼容默认展开的反写,徒增 store 复杂度。
    - "空目录隐藏箭头"逻辑:子目录 `children !== undefined && children.length === 0` 时不渲染展开箭头,但根 row 永远显示(根永远是目录,保留折叠 / 展开 affordance)。
    - 让"空 / 非空"在父目录加载完后立即生效(而非用户点击展开后才知道),`loadDirChildren` 末尾 fire-and-forget 对每个新 child dir 跑 `probeDirEmptiness`:**只在结果为空时**把 child.children 置 [],非空保留 undefined(留给用户首次展开时 `loadDirChildren` 全量加载)——这样不破坏懒加载初衷,只多打一次"是否为空"的轻量 readDir。
    - race 守卫:探测 await `readDir` 期间用户可能已点击展开 → `loadDirChildren` 抢先把 children 填好;探测 resolve 后必须重判 `children !== undefined`,命中就放弃覆盖。失败(权限等)静默 —— 等用户真正点开时 `loadDirChildren` 会暴露真实错误。
    - dragstart 必须先 `closeContextMenu() + cancelInline()`:菜单 / 行内 input 在拖拽期间残留,drop 时全局 pointerdown 会把行内 input 误提交。
    - `effectAllowed` 必须是 `'all'` 而非 `'copyLink'`:dropEffect='move' 必须在 effectAllowed 子集内,否则浏览器视为非法 → 树内 drop 拒绝;编辑器侧自行计算 dropEffect 不受 source 宽放影响。
    - **hover-expand**: 拖拽悬停折叠目录 500ms 自动展开(VSCode 行为),`armHoverExpand(dstDir)` 在 `onRowDragOver` 命中目录 row 时挂 timer;切到别的目录 / 文件 row / 容器空白 / dragend / drop 都必须 `clearHoverExpandTimer()`,否则 timer 跨拖拽残留,下次悬停同目录 500ms 内会触发"幽灵展开"。文件 row 解析到的父目录已展开(否则文件不可见),不挂 timer。根目录走 `rootCollapsed` 而非 `workspace.expandedDirs`,所以 `armHoverExpand` 对根 path 走独立分支。
- **`openPathInTab` 的 `{ silent: true }` 选项(v0.6.0 启动恢复专用)**: 默认行为仍是"读失败弹原生错误框"——满足文件树 / Ctrl+P / 命令面板等 UI 入口的用户预期。**启动恢复**走 `openPathInTab(p, { silent: true })`:被外部删的文件属"可预期的少数情况",静默跳过 + console.warn,**不**在 setup 期间连弹错误框;不引入第二个并行函数(`openPathInTabSilent`)是因为 silent 仅是错误反馈策略的差异,主流程完全重合。**不要**在其他 UX 场景用 silent —— 用户主动点开文件应该被告知失败原因。
- **openTabs restore 必须 snapshot 本地副本,不读 `activeWorkspace.openTabs`**(v0.6.0 踩坑): `documentStore.openFilePaths + currentFilePath` watcher 会同步调 `setOpenTabsForActiveWorkspace(...)` 写回 workspaces;启动期任何 openPathInTab(CLI `initialFile` / `startupMode === 'last-file'` 这两段)都会先 fire watcher 把 `activeWorkspace.openTabs` 压成"当前 documents 状态"。**race**:restore block 直接读 `activeWorkspace.openTabs` 会被污染 → 7 个 tab 只 restore 1 个 → 500ms debounce 把 1 个落盘,持久污染下次启动。**正确做法**:`loadFrom` 之后**立即**把 openTabs / activeTab 拍到本地变量(`.slice()` 防数组别名),restore block 用本地副本,不读 store。后续改 restore 链路时不要回退到读 store。
- **openTabs restore 走 `openPathsInTabs` 批量并行,不走多次串行 `openPathInTab`**(v0.6.0): 串行 `for await openPathInTab(p)` 会让 N 个标签肉眼可见地"一个个出现"——IO 是大头(readTextFile 在网络盘 / 慢盘尤甚),且每次 openPathInTab 内的 `documents.value.set` 触发 reactive → Vue 增量重渲 TabBar,7 个 tab 就是 7 次 update。`openPathsInTabs` 把 N 次 readTextFile 收进 `Promise.all` 并发(N 个文件同时 in-flight),commit 阶段循环无 await、所有 reactive 触发在同一 microtask,TabBar 一次拿到 N 个 tab。**实现要点**:`pristineConsumed` 显式跟踪——批量的 IO 阶段是并行的,不能用串行版"装一个就 activeDoc 变了"的隐式语义;Promise.all 失败先收集,**commit 阶段**再处理(silent 走 console.warn,非 silent 顺次 `await message`),不在 IO 阶段发弹窗以免同 tick 并发 fire。后续若新增"批量打开"路径(例如文件树多选开标签)应复用这条 API,不要新写一遍串行循环。
- **openTabs 落盘前 dedupe + cap,启动恢复二次保险**(v0.6.0 踩坑): 三层保护防止"重启后同一个文件出现两个 tab + dev 进入主线程被拖死"。**根因**:`documentStore.openFilePaths` 允许同 path 多 tab(`openPathInNewTab` 中键强制新开是显式语义,UI 需要看到重复 tab),但持久化层不应无脑照搬重复项到 velo-workspaces.json —— 历史版本曾因不 dedupe 让 openTabs 累积同 path 数千条,启动时 `openPathsInTabs` 把每条都 createTab → TabBar 渲染数千个 tab → WebView2 主线程被拖死,表现为"dev 进入卡死什么也点不了 + devtools 打不开"。**修法三层**:① `workspaceStore.setOpenTabsForActiveWorkspace` 写盘前 `dedupePreserveOrder` + `slice(0, OPEN_TABS_PERSIST_CAP)`(50,VSCode 同档体感),UI 仍允许多实例 tab 但持久化只记一份;② `normalizeWorkspaceState` 加载时同样走 dedupe + cap,旧 v4 JSON 已被污染也能清洗;③ `documentStore.openPathsInTabs` 启动恢复 commit 阶段对每个 path 先 `findTabByPath` —— 已开就 skip(不重复 loadContent),与 `openPathInTab` "已开则复用"语义对齐(否则 `startupMode='last-file'` 段先 `openPathInTab(lastFile)`、随后 `openPathsInTabs(persistedOpenTabs)` 又跑 → active 已挂 lastFile 不是空白 → `canReusePristine=false` → createTab + loadContent → 同一 path 双 tab,现象是"关掉再开变两个一样的")。**dedupe vs UI 多实例**:`openFilePaths` 仍允许同 path 重复项(中键新开 tab 是显式语义,用户能看到 N 个相同 .md),持久化层面 dedupe 是**有意为之**——重启工作区不期望看到 N 个相同 .md 各占一个 tab,VSCode 重开也是按 path 去重。后续如果要做"打开第 N 个相同文件的实例"持久化(真支持每个实例独立恢复),需要在 WorkspaceState 引入 instanceId 而非 path 唯一,目前不必。
