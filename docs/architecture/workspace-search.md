# Workspace Search

> **本文件负责**: Ctrl+P 快速打开、Ctrl+Shift+P 命令面板与 Ctrl+Shift+F 工作区全文搜索。
>
> **何时阅读**: 改 `QuickOpenPanel.vue`、`CommandPalettePanel.vue`、`WorkspaceSearchPanel.vue`、`quickOpenIndex.ts`、`commandPalette.ts`、`workspaceSearch.ts`、fuzzy scoring 或最近文件语义时。
>
> **先记住**:
> - Ctrl+P 索引是 per-root 内存缓存，fs.watch 只标记 stale，不做局部 patch。
> - 最近文件分两层:Ctrl+P 用 per-workspace recent;顶栏用全局 recent。
> - Ctrl+Shift+P 命令面板是 App shell 的轻量聚合入口,不是 VSCode 式全局命令系统。
> - Ctrl+Shift+F MVP 实时遍历 raw markdown，不建持久索引。
> - WYSIWYG raw offset 只能在 ordinal 可对齐时定位，否则只打开文件。
> - Ctrl+Shift+F 面板在 v0.6.x 改为侧栏内嵌 tab,不再是 Teleport 浮层。
>
> **相关文件**: [架构索引](../ARCHITECTURE.md) / [文件树](./file-tree.md) / [查找替换](./find-replace.md)


## 设计要点

- **Ctrl+P 查找文件:工作区 .md 索引 + fzf 评分 + 最近优先双分区**(v0.5.2): 全局快捷键挂 `App.vue:onKeydown`(同 Ctrl+F / Ctrl+S 同一处),无工作区静默 return。索引走单例 `Map<root, { entries, stale, pending }>`(`src/utils/quickOpenIndex.ts`),首次 `ensureIndex(root)` 递归 readDir BFS 收集 .md(隐藏目录 `.git` 等过滤),pending promise 挂在 slot 上防并发重复 walk。**失效策略走”标记 stale 而非局部 patch”**:工作区根 fs.watch 的 `scheduleDirtyFlush` 任何脏事件都 `invalidate(root)`,下次面板打开重扫;切工作区 `clearAll()` 清整张表。与 FileTree “脏目录集 + 子树重拉”同款哲学,简单可靠。**fuzzy 评分**(`src/utils/fuzzy.ts:fuzzyScore`)做子序列匹配 + 评分:连续段长度平方累加 + 词首字符(分隔符 / `_` / `-` / `.` / 空格后)bonus + 起始位置惩罚。**最近优先双分区**:面板始终把结果拆成”最近打开”(`workspaceStore.activeWorkspace.recentFiles`,头部=最新,cap 10)+ “其他”(扣掉 recent 的剩余)两段;**最近段保留 recent 顺序不被 fuzzy score 重排**(语义:最近优先 > 相关性),query 激活时只对该段做”过滤不重排”;其他段空 query 走 alpha、有 query 按 score 降序。**recentFiles 持久化粒度 per-workspace**(与 expandedDirs/lastFile 同栈在 velo-workspaces.json),`setLastFile(path)` 内部自动 push;`renamePathPrefix` 跟随重写避免移动 / 重命名后 recent 指向死路径;v0.5.3 计划中的”跨工作区最近文件”是另一套全局粒度,与本字段不冲突。**结果排版**:文件名(保留 .md 后缀)+ 灰色相对路径副标(VSCode/Obsidian 风格),命中字符段**只用 `font-bold` 加粗不写独立颜色**,继承父容器 color;选中行背景走 `color-mix(--md-primary-color 12%)`,**不**叠暗色 gray-800 底,避免主色 + 蓝灰底叠出深蓝。**暗色面板底色**用 `#1a1a1a` 与 App 主底对齐,**不**用 Tailwind `gray-900`(后者偏 slate-blue,与 App 整体中性灰冲突)。**面板生命周期**:`v-if` 控制实例存活,关闭即销毁;打开走 `documentStore.confirmDiscardIfDirty()` → `openPath()` → `workspaceStore.setLastFile()`,与 FileTree 单击同条契约(同时把 path 写入 recentFiles)

- **Ctrl+Shift+F 全文搜索:JS 端实时扫 .md + raw 命中定位**(v0.5.2,**v0.6.x 改为侧栏内嵌**): 全局快捷键同样挂 `App.vue:onKeydown`,无工作区静默 return;左贴边 ActivityBar 的”全局搜索”入口复用同条 `toggleSidebarTab('search')` 路径,不另起侧栏搜索状态。**v0.6.x 形态**:面板是侧栏第三个 tab(`workspaceStore.sidebarTab === 'search'`),与 FileTree / EditorOutline 在 `Sidebar.vue` 里互斥 v-if;不再是 Teleport 浮层。视觉节奏跟 EditorOutline 对齐(p-2 / pr-2 内边距 + 顶栏 1px 边线),顶栏同时塞 Aa / W / .* / 停止 等控件,关闭走 Esc / 再次点 ActivityBar 搜索图标 / emit('update:open', false) → Sidebar 转发 `workspace-search-close` → App.vue 把 `leftPanelView` 置 null 收起侧栏。MVP 不建持久索引:每次 query debounce 后走 `src/utils/workspaceSearch.ts` 递归 `readDir` BFS(隐藏目录整段跳过)→ `readTextFile` → 复用查找替换的 `buildPattern` 跑 RegExp,按行匹配,结果只展示命中行(不渲染上下文行,不展示行号),同一行多命中拆多条 row;目录 / 文件读取失败按 quickOpen 同款静默跳过。进度按 scanning/searching/canceled/done 汇报,取消只能在每次 Tauri fs await 之后生效(不能中断已发出的 plugin-fs 调用),旧 run 结果用 token 丢弃;v-if 卸载时 `onBeforeUnmount` 兜底 `cancelActive` 避免悬挂 controller。**点击结果不自动关闭面板**(v0.6.x 行为变化):侧栏不遮挡编辑器,让用户连续点多个结果,关闭走 Esc / 再次点 ActivityBar 搜索图标。**命中段高亮与 FindReplace Decoration 共用 `.velo-find-match` 全局样式**(`src/styles/_editor-base.scss` 定义的金色 rgba(255,215,0,.35)),不依赖 `--md-primary-color`:用户自定义主色过浅时 `color-mix(..., 22%, transparent)` 几乎不可见,但金色饱和度高、与主色解耦,浅 / 深主题下都保证可见;与编辑器内 FindReplace 视觉一致。**hover 行底色与右键菜单对齐**(`hover:bg-gray-100 dark:hover:bg-gray-700`,与 `TabContextMenu.vue` / `FileTreeContextMenu.vue` 同款);选中行仍用主色 `color-mix(--md-primary-color 12%)` —— 选中态是"主色语义"用主色系、hover 态是"系统反馈"走菜单色系,两层不混。**hover / selected 拆成两个独立 state**:`hoveredFlatIndex` 由 mouseenter/mouseleave 改,只挂 `.velo-ws-hovered` class 显示菜单色底;`selectedFlatIndex` 由**键盘 ArrowUp/Down + Click 共同改**,走 inline style 主色底(inline style specificity 最高,selected + hover 同条时显示主色,"hover 是预览、selected 是确认")。Click 也改 selectedFlatIndex,因为 v0.6.x 面板不自动关闭:连续点多个结果时需要保留"最后一次点的是哪条"的视觉锚点,以及让紧随其后的 Enter 仍打开这条。早期版本把 hover 合并进 selectedFlatIndex(`@mousemove="selectRow"`),导致 hover 立即触发主色底,菜单色 hover 永远看不到;再后来删 mousemove 又让 hover 完全失去视觉反馈,鼠标移到其他行不会高亮。拆成两个独立 state 才让两层配色系统真正共存 —— 鼠标 hover 其他行时,hovered 那条菜单色、selected 那条主色,同时可见;Enter 仍按 keyboard / click selected 打开、Click 仍直接 emit hit。**文件夹 scope 子目录搜索(v0.6.0)**: `searchWorkspaceMarkdown` 第 6 个可选参数 `scopeDir: string | null`,BFS 起点由 scopeDir 决定(null → 工作区根,等于旧行为);relPath 也按 scopeDir 切片,scope 是子目录时显示如 `guide.md` 而不是 `docs/guide.md`。scope 入口只走文件树右键菜单`FileTreeContextMenu` 加的「在此文件夹中搜索」(仅目录节点,根节点/根上下文/文件无此项)→ `FileTree.vue` emit `search-in-folder` → `Sidebar.vue` 透传给 App.vue → `workspaceSearchScopeDir` ref 写入路径 + `showSidebarTab('search')` 切到 search tab。App.vue 的 scope 是单一来源,通过 prop `workspaceSearchScopeDir` 透传给 panel;panel header 在 query 行下方显示 scope chip(Folder 图标 + 相对工作区根路径 + × 按钮),点 × emit `clear-scope` → App.vue 清回 null。**scope 不持久化**:切工作区 / 重开面板 → scope 默认 null —— 用户重开面板通常想"重新看全工作区",保留旧子目录反直觉。**点击定位按编辑器模式分两路**(App.vue `selectWorkspaceSearchHit`):
  - **source mode**:CM6 `findMatches` 在原始 markdown 整串上跑,offset 与 raw 1:1。优先 `matches[hit.matchOrdinal]`;若 ordinal 越界(文件被改过),fallback `getRangeText(rawFrom, rawTo) === matchText` 校验文本未变后用 raw offset 跳。
  - **WYSIWYG**:PM `findMatchesInDoc` 只走 text 节点,跳过 `code_block` / `image` / `mermaid` 等所有非 text 节点;raw scan 是 per-line 全串正则,**包含**这些节点的源码内容 —— 两侧计数规则天然不一致,不能跨节点对齐。直接信任 `pmMatches[hit.matchOrdinal]`:raw ordinal 与 PM pmMatches 在 prose 节点(paragraph / heading / list)上对齐,因为 PM text node 是一次 exec,同段 N 个 match ordinal 0..N-1,与 raw per-line scan 一致;raw 命中若落在 `code_block` / `image` / `mermaid` 节点里,PM pmMatches[ordinal] undefined → 静默放弃,文件已 `openPathInTab` 打开,用户至少能浏览到目标行附近。**不自动切 source mode**:避免劫持用户当前编辑模式(workspace search 与 `App.vue` 跨模式光标 / 滚动同步 watch 走的不是同条路径,后者只服务主动 Ctrl+` 入口)。
  - 早期版本曾校验 `pmMatches.length === hit.fileMatchCount` 试图过滤"文件被改过"的情况,但因上面计数规则差异,等价于"文件不能含任何特殊节点",含图 / mermaid / 代码块的笔记 100% 报"结果已过期",已去除。
  - `data-workspace-search-panel` 选择器仍挂在面板根 div 上,App.vue onKeydown 的 `closest('[data-fr-panel], [data-command-palette-panel]')` 靠它判断焦点是否在面板内以避免重复触发全局快捷键 —— 侧栏内嵌之后面板不再被 Teleport 到 body,选择器仍生效(只检查 DOM 树)。

- **Ctrl+Shift+P 命令面板:App shell 命令聚合,不引入完整命令系统**(v0.5.7): 命令面板沿用 QuickOpen 的顶部浮层、键盘导航与 `fuzzyScore` 评分,但搜索对象是 App shell 的可执行操作而不是文件索引。命令列表在 `App.vue` 组装,因为打开 / 保存 / 导出 / 查找替换 / 源码模式 / 左侧面板这些动作的状态与副作用都由 App shell 持有;`CommandPalettePanel.vue` 只负责输入、分组展示、disabled 呈现和执行选中项,`src/utils/commandPalette.ts` 只做 query 归一化、跨字段 fuzzy 匹配与 title 高亮切段。这里**故意不做 VSCode 式 command registry / context key / 参数化命令系统**,避免把轻量入口变成第二套 shell 状态机。最近文件条目读取全局 `recentFilesStore.entries`,执行仍复用 App 的 `openRecentFile(path)` 路径;Ctrl+P 的 per-workspace recent 继续只服务当前工作区快速打开。工作区相关命令无 active root 时保留可见但 disabled,用于告诉用户”功能存在,需要先打开工作区”,而 Ctrl+P 原快捷键仍保持无工作区静默。

- **工作区搜索替换(v0.6.0)**: IO 与搜索逻辑拆开 —— `WorkspaceSearchPanel.vue` 只负责 UI(query / replacement / 命中行渲染),`utils/workspaceSearch.ts` 的 `applyWorkspaceReplace(hits, plan, dirtyPaths)` 是编辑器无关的纯函数 IO,App.vue 编排二者。流程:面板 emit `apply-replace` 携带 `{ hits, replacement, scope: 'one' | 'all' }` → App.vue 从 `documentStore.documents.values()` snapshot dirty tab 的 fullPath 集合(替换开始瞬间,避免 race)→ 调 `applyWorkspaceReplace` → 遍历 changedFiles 把磁盘已写的新内容同步到打开中的 clean tab(走 `documentStore.loadContentInto`,同步 content + lastSavedContent + 重建 watch) → 写 `replaceStatus` prop + `rerunToken++` 触发 panel 重跑搜索。**dirty tab 一律跳过**:用户编辑器里有未保存修改 → 替换读取的是磁盘基线,直接覆盖会毁掉用户编辑。全部替换完成后 `formatReplaceStatus` 把"已替换 X 处 / Y 个文件因有未保存修改被跳过 / Z 个文件读写失败"汇总到面板底部一次性 status,清空由用户后续搜索自然接管。**「替换」语义 = 当前选中条目所在文件的所有命中**:对齐编辑器内 Ctrl+H 但放宽到"按文件替换全部" —— 用户既然点了这条,大概率想清理整个文件;若想逐条改,先单文件打开再 Ctrl+H 即可。**「全部替换」= 当前所有结果命中文件**。**RegExp 复用 `replaceInText`**:regex 模式下保留 `$1`/`$2` 反向引用(caseSensitive / wholeWord / regex 选项与搜索阶段共享 `buildPattern`,语义一致)。**重跑触发用 token 计数器**:`rerunToken` 是单调递增整数,prop watcher 看到值变化就 `scheduleSearch` —— 比 `watch(() => initialQuery)` 更明确("有重跑信号"),且 initialQuery 不变不会触发。**未启用持久索引**:替换写盘后立即重跑搜索,fs:watch 也会触发 documentStore 的 `checkExternalChange`,两条路径在结果刷新上冗余但安全。
