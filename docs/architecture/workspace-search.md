# Workspace Search

> **本文件负责**: Ctrl+P / Ctrl+Shift+P 统一命令面板与 Ctrl+Shift+F 工作区全文搜索。
>
> **何时阅读**: 改 `QuickCommandPanel.vue`、`WorkspaceSearchPanel.vue`、`quickCommand.ts`、`quickOpenIndex.ts`、`commandPalette.ts`、`workspaceSearch.ts`、fuzzy scoring 或最近文件语义时。
>
> **先记住**:
> - Ctrl+P / Ctrl+Shift+P 合并为单一前缀分发面板(v0.6.2):输入框首字符决定模式('' = file / '>' = command / '@' = symbol 当前文档标题 / ':' = line 跳行号;# workspace-symbol 暂缓)。
> - file 模式空 query 时列表顶部插 @/:/> 介绍行(isHelp 标记),resetSelectionToFirst 跳过 → 默认 Enter 仍打开首文件;选中介绍行即填入对应前缀切模式(只 > 有直接快捷键 Ctrl+Shift+P)。
> - file 模式索引是 per-root 内存缓存,fs.watch 只标记 stale,不做局部 patch。
> - 最近文件分两层:file 模式用 per-workspace recent;顶栏用全局 recent。
> - command 模式是 App shell 的轻量聚合入口,不是 VSCode 式全局命令系统。
> - Ctrl+Shift+F MVP 实时遍历 raw markdown，不建持久索引。
> - WYSIWYG raw offset 只能在 ordinal 可对齐时定位，否则只打开文件。
> - Ctrl+Shift+F 面板在 v0.6.x 改为侧栏内嵌 tab,不再是 Teleport 浮层。
>
> **相关文件**: [架构索引](../ARCHITECTURE.md) / [文件树](./file-tree.md) / [查找替换](./find-replace.md)


## 设计要点

- **统一命令面板(v0.6.2):前缀分发 + file 模式**(合并原 Ctrl+P 查找文件 + Ctrl+Shift+P 命令面板;@ symbol / : line 已接入,# workspace-symbol 暂缓): 顶部居中 Teleport 浮层(z-120),一个输入框,首字符决定模式 —— `''` = file、`>` = command。前缀字符保留在输入框 raw value 里(用户键入 `>` / `@` 即可见),`src/utils/quickCommand.ts:parseQuickCommand` 剥前缀 + 一个可选空格成 `{ mode, text }`,text 喂给各模式过滤函数;输入框无单独模式徽标,placeholder 随 mode 切换。两套行视图统一成 `UnifiedRow` / `UnifiedSection`,共用一套 `flatRows` / `selection` / ArrowUp/Down/Enter/Esc 跨段线性切换。Ctrl+P / Ctrl+Shift+P 已开在同模式 → 关,不同模式 → 切(切模式靠 App.vue 的 mountKey 强制 remount 让新 `initialQuery` 生效,因 `open` watcher 只在 false→true 触发)。`data-quick-command-panel` 挂在面板根,App.vue onKeydown 的 `closest('[data-fr-panel], [data-quick-command-panel]')` 靠它判焦点是否在面板内以避免重复触发全局快捷键。**file 模式**: 全局快捷键挂 `App.vue:onKeydown`(同 Ctrl+F / Ctrl+S),无工作区静默 return;索引走单例 `Map<root, { entries, stale, pending }>`(`src/utils/quickOpenIndex.ts`),首次 `ensureIndex(root)` 递归 readDir BFS 收集 .md(隐藏目录 `.git` 等过滤),pending promise 挂在 slot 上防并发重复 walk。**失效策略走”标记 stale 而非局部 patch”**:工作区根 fs.watch 的 `scheduleDirtyFlush` 任何脏事件都 `invalidate(root)`,下次面板打开重扫;切工作区 `clearAll()` 清整张表。与 FileTree “脏目录集 + 子树重拉”同款哲学,简单可靠。**fuzzy 评分**(`src/utils/fuzzy.ts:fuzzyScore`)做子序列匹配 + 评分:连续段长度平方累加 + 词首字符(分隔符 / `_` / `-` / `.` / 空格后)bonus + 起始位置惩罚。**最近优先双分区**:面板始终把结果拆成”最近打开”(`workspaceStore.activeWorkspace.recentFiles`,头部=最新,cap 10)+ “其他”(扣掉 recent 的剩余)两段;**最近段保留 recent 顺序不被 fuzzy score 重排**(语义:最近优先 > 相关性),query 激活时只对该段做”过滤不重排”;其他段空 query 走 alpha、有 query 按 score 降序。**recentFiles 持久化粒度 per-workspace**(与 expandedDirs/lastFile 同栈在 velo-workspaces.json),`setLastFile(path)` 内部自动 push;`renamePathPrefix` 跟随重写避免移动 / 重命名后 recent 指向死路径;v0.5.3 计划中的”跨工作区最近文件”是另一套全局粒度,与本字段不冲突。**结果排版**:文件名(保留 .md 后缀)+ 灰色相对路径副标(VSCode/Obsidian 风格),命中字符段**只用 `font-bold` 加粗不写独立颜色**,继承父容器 color;选中行背景走 `color-mix(--md-primary-color 12%)`,**不**叠暗色 gray-800 底,避免主色 + 蓝灰底叠出深蓝。**暗色面板底色**用 `#1a1a1a` 与 App 主底对齐,**不**用 Tailwind `gray-900`(后者偏 slate-blue,与 App 整体中性灰冲突)。**面板生命周期**:`v-if` 控制实例存活,关闭即销毁;打开走 `documentStore.openPathInTab` → `workspaceStore.setLastFile()`,与 FileTree 单击同条契约(多标签模型下当前脏盘不丢,无需脏盘确认)

- **统一命令面板 · file 模式 create-if-not-found:没找到 → 新建文件**(v0.6.2): file 模式 query 非空、无任何模糊命中(最近 / 其他两段都空)、有 activeRoot 且名称合法时,在列表顶部插一行「新建文件: <name>.md」,Enter 即建盘 + 打开。打开半段复用 `openPathInTab` + `setLastFile`(与 `openFileRow` 同条契约),建盘半段复用 FileTree 的 `writeTextFile(path, '')` + `finalName` / `validateName`(`@/components/Sidebar/treeUtils`)。**故意不复用 `file.new` 命令**:它只开未命名临时 tab(`documentStore.newDoc()`),不写盘也不接受文件名,语义是"新草稿"而非"在工作区建一个命名文件";把两种语义塞进一个命令会 muddy。**只做"没找到"兜底,不在有命中时也插**:避免与模糊结果抢 `resetSelectionToFirst` 的默认选中(有命中时 Enter 该打开第一条匹配,而非意外建文件)。**`exists` 守门防覆写**:大小写不敏感 FS(Windows)下 `foo.md` 与 `Foo.md` 冲突、或竞态下文件刚被外部建出,`writeTextFile` 默认 truncate 会丢数据;建盘前先 `exists`,已存在则跳过写直接打开。`validateName` 传 `siblingNames=null` 不做同名判定,交给 `exists` 兜底。

- **统一命令面板 · file 模式顶部前缀介绍行(@/:/>,VSCode `?` help 风格)**(v0.6.2): file 模式 + 空 query + 工作区有 .md 文件时,在列表顶部(最近打开之上)插三行,每行 = 前缀图标(Terminal/AtSign/ListOrdered,图标本身即前缀视觉,不重复写 `>`/`@`/`:` 字符)+ 模式名 + 副标用途(只 `>` 带直接快捷键 `Ctrl+Shift+P`,`@` / `:` 是面板内前缀、无独立快捷键)。**选中即 `switchToPrefix(prefix)`**:把 `query.value` 置为该前缀 → `parseQuickCommand` 自然分发到对应模式(`:` 会触发 line-enter 进 `:` 生命周期,与手敲 `:` 同路径)。**`isHelp` 标记不抢默认选中**:`resetSelectionToFirst` 跳过 `isHelp` 行,默认选中仍是第一个文件行 —— Enter 打开首文件(保肌肉记忆),ArrowUp 才上到介绍行。**异步索引加载的选中竞态**:面板打开时 `allEntries` 还空 → `resetSelectionToFirst` 把 selection 置 `{0,0}`;索引异步加载完 `sections` 重算后 `{0,0}` 命中的是第一行介绍行(存在)→ 旧的 flatRows watcher 只在"选中行消失"时重置,会卡在介绍行。**修复**:watcher 改成"选中行消失 **或** 停在 `isHelp` 行"都重置(`!cur || cur.row.isHelp`),让索引加载后选中正确落到首文件。**何时隐藏**:非空 query(用户在搜文件)或工作区无 .md 文件(走"工作区内没有 .md 文件"空态)时不显示介绍行。

- **Ctrl+Shift+F 全文搜索:JS 端实时扫 .md + raw 命中定位**(v0.5.2,**v0.6.x 改为侧栏内嵌**): 全局快捷键同样挂 `App.vue:onKeydown`,无工作区静默 return;左贴边 ActivityBar 的”全局搜索”入口复用同条 `toggleSidebarTab('search')` 路径,不另起侧栏搜索状态。**v0.6.x 形态**:面板是侧栏第三个 tab(`workspaceStore.sidebarTab === 'search'`),与 FileTree / EditorOutline 在 `Sidebar.vue` 里互斥 v-if;不再是 Teleport 浮层。视觉节奏跟 EditorOutline 对齐(p-2 / pr-2 内边距 + 顶栏 1px 边线),顶栏同时塞 Aa / W / .* / 停止 等控件,关闭走 Esc / 再次点 ActivityBar 搜索图标 / emit('update:open', false) → Sidebar 转发 `workspace-search-close` → App.vue 把 `leftPanelView` 置 null 收起侧栏。MVP 不建持久索引:每次 query debounce 后走 `src/utils/workspaceSearch.ts` 递归 `readDir` BFS(隐藏目录整段跳过)→ `readTextFile` → 复用查找替换的 `buildPattern` 跑 RegExp,按行匹配,结果只展示命中行(不渲染上下文行,不展示行号),同一行多命中拆多条 row;目录 / 文件读取失败按 quickOpen 同款静默跳过。进度按 scanning/searching/canceled/done 汇报,取消只能在每次 Tauri fs await 之后生效(不能中断已发出的 plugin-fs 调用),旧 run 结果用 token 丢弃;v-if 卸载时 `onBeforeUnmount` 兜底 `cancelActive` 避免悬挂 controller。**点击结果不自动关闭面板**(v0.6.x 行为变化):侧栏不遮挡编辑器,让用户连续点多个结果,关闭走 Esc / 再次点 ActivityBar 搜索图标。**命中段高亮与 FindReplace Decoration 共用 `.velo-find-match` 全局样式**(`src/styles/_editor-base.scss` 定义的金色 rgba(255,215,0,.35)),不依赖 `--md-primary-color`:用户自定义主色过浅时 `color-mix(..., 22%, transparent)` 几乎不可见,但金色饱和度高、与主色解耦,浅 / 深主题下都保证可见;与编辑器内 FindReplace 视觉一致。**hover 行底色与右键菜单对齐**(`hover:bg-gray-100 dark:hover:bg-gray-700`,与 `TabContextMenu.vue` / `FileTreeContextMenu.vue` 同款);选中行仍用主色 `color-mix(--md-primary-color 12%)` —— 选中态是"主色语义"用主色系、hover 态是"系统反馈"走菜单色系,两层不混。**hover / selected 拆成两个独立 state**:`hoveredFlatIndex` 由 mouseenter/mouseleave 改,只挂 `.velo-ws-hovered` class 显示菜单色底;`selectedFlatIndex` 由**键盘 ArrowUp/Down + Click 共同改**,走 inline style 主色底(inline style specificity 最高,selected + hover 同条时显示主色,"hover 永远看不到;再后来删 mousemove 又让 hover 完全失去视觉反馈,鼠标移到其他行不会高亮。拆成两个独立 state 才让两层配色系统真正共存 —— 鼠标 hover 其他行时,hovered 那条菜单色、selected 那条主色,同时可见;Enter 仍按 keyboard / click selected 打开、Click 仍直接 emit hit。**文件分组折叠(v0.6.x)**: 每个文件分组 header 改成 `<button>`(整行可点,沿用 FileTree 同款,而非 EditorOutline 仅 chevron 可点),左侧加 `ChevronRight + rotate-90` 与 FileTree / EditorOutline 同款 chevron idiom,`aria-expanded` 暴露折叠态给屏幕阅读器;点 row 切 `collapsedFiles: Set<string>`(key = file fullPath)。**状态放组件本地,不持久化** —— 与 `showReplace` 同款语义:`(A)` 避免引入 WORKSPACES_VERSION bump + path-prefix rename/move 处理(像 `expandedDirs` 那套);`(B)` 避免持久折叠指向已不在结果里的文件导致的 stale state 清理逻辑;`(C)` 与"切 sidebar tab / 改 query / rerunToken 都不主动清空,只要分组还在结果集里就保持折叠"的用户直觉对齐 —— 行为对齐 FileTree 的 expandedDirs:折叠态在搜索期内稳定,跨 search 复用同文件路径时不"自动重置"。**折叠的 IO 边界**:`hasResults` 与 `applyReplace` 都从 `flatRows` 改成 `groups`(后者才是搜索阶段产出的全集)—— flatRows 被折叠过滤后会让"全部命中数为 0"的假象传到按钮 disabled 态,折叠所有组后「替换」就点不动了,反直觉(用户折叠只是不想看,不是想跳过);`groups.find(g => g.file.fullPath === filePath)?.hits` 与 `groups.flatMap(g => g.hits)` 保证替换 IO 与折叠态正交。**键盘导航**:`flatRows` 计算属性跳过 `collapsedFiles` 命中的组,ArrowUp/Down 自动不进入折叠中的 hit;`clampSelection` 用 `Math.min(idx, n-1)`(保留位置)而非旧版归零,让中间折叠时选区锚点跳到最近可见行而非从头开始。**折叠态用 Set 重新赋值触发响应式**:Vue 3 ref 对 Set 的 in-place mutation 不会自动 trigger(沿用 outlineStore "转 array 写回 reactive 对象"的套路);`toggleCollapsed` 内部 `new Set(prev)` + `add/delete` + `ref.value = next` 三步完成,避免 ref 看到同一引用而不更新。**文件夹 scope 子目录搜索(v0.6.0)**: `searchWorkspaceMarkdown` 第 6 个可选参数 `scopeDir: string | null`,BFS 起点由 scopeDir 决定(null → 工作区根,等于旧行为);relPath 也按 scopeDir 切片,scope 是子目录时显示如 `guide.md` 而不是 `docs/guide.md`。scope 入口只走文件树右键菜单`FileTreeContextMenu` 加的「在此文件夹中搜索」(仅目录节点,根节点/根上下文/文件无此项)→ `FileTree.vue` emit `search-in-folder` → `Sidebar.vue` 透传给 App.vue → `workspaceSearchScopeDir` ref 写入路径 + `showSidebarTab('search')` 切到 search tab。App.vue 的 scope 是单一来源,通过 prop `workspaceSearchScopeDir` 透传给 panel;panel header 在 query 行下方显示 scope chip(Folder 图标 + 相对工作区根路径 + × 按钮),点 × emit `clear-scope` → App.vue 清回 null。**scope 不持久化**:切工作区 / 重开面板 → scope 默认 null —— 用户重开面板通常想"重新看全工作区",保留旧子目录反直觉。**点击定位按编辑器模式分两路**(App.vue `selectWorkspaceSearchHit`):
  - **source mode**:CM6 `findMatches` 在原始 markdown 整串上跑,offset 与 raw 1:1。优先 `matches[hit.matchOrdinal]`;若 ordinal 越界(文件被改过),fallback `getRangeText(rawFrom, rawTo) === matchText` 校验文本未变后用 raw offset 跳。
  - **WYSIWYG**:PM `findMatchesInDoc` 只走 text 节点,跳过 `code_block` / `image` / `mermaid` 等所有非 text 节点;raw scan 是 per-line 全串正则,**包含**这些节点的源码内容 —— 两侧计数规则天然不一致,不能跨节点对齐。直接信任 `pmMatches[hit.matchOrdinal]`:raw ordinal 与 PM pmMatches 在 prose 节点(paragraph / heading / list)上对齐,因为 PM text node 是一次 exec,同段 N 个 match ordinal 0..N-1,与 raw per-line scan 一致;raw 命中若落在 `code_block` / `image` / `mermaid` 节点里,PM pmMatches[ordinal] undefined → 静默放弃,文件已 `openPathInTab` 打开,用户至少能浏览到目标行附近。**不自动切 source mode**:避免劫持用户当前编辑模式(workspace search 与 `App.vue` 跨模式光标 / 滚动同步 watch 走的不是同条路径,后者只服务主动 Ctrl+` 入口)。
  - 早期版本曾校验 `pmMatches.length === hit.fileMatchCount` 试图过滤"文件被改过"的情况,但因上面计数规则差异,等价于"文件不能含任何特殊节点",含图 / mermaid / 代码块的笔记 100% 报"结果已过期",已去除。
  - `data-workspace-search-panel` 选择器仍挂在面板根 div 上,App.vue onKeydown 的 `closest('[data-fr-panel], [data-quick-command-panel]')` 靠它判断焦点是否在面板内以避免重复触发全局快捷键 —— 侧栏内嵌之后面板不再被 Teleport 到 body,选择器仍生效(只检查 DOM 树)。

- **统一命令面板 · command 模式:App shell 命令聚合,不引入完整命令系统**(v0.5.7): 搜索对象是 App shell 的可执行操作而不是文件索引(顶部浮层、键盘导航、fuzzyScore 与 file 模式共用,见上)。命令列表在 `App.vue` 组装,因为打开 / 保存 / 导出 / 查找替换 / 源码模式 / 左侧面板这些动作的状态与副作用都由 App shell 持有;`QuickCommandPanel.vue` 只负责输入、分组展示、disabled 呈现和执行选中项,`src/utils/commandPalette.ts` 做跨字段 fuzzy 匹配与 title 高亮切段。这里**故意不做 VSCode 式 command registry / context key / 参数化命令系统**,避免把轻量入口变成第二套 shell 状态机。最近文件条目读取全局 `recentFilesStore.entries`,执行仍复用 App 的 `openRecentFile(path)` 路径;Ctrl+P 的 per-workspace recent 继续只服务当前工作区快速打开。工作区相关命令无 active root 时保留可见但 disabled,用于告诉用户”功能存在,需要先打开工作区”,而 Ctrl+P 原快捷键仍保持无工作区静默。

- **统一命令面板 · symbol 模式(@):当前文档标题跳转,跨编辑器模式两路定位**(v0.6.2): 搜索对象是**当前文档**的标题树,不是工作区(`documentStore.content`,无 fs 调用;工作区级 symbol 是后续 `#` 模式)。标题解析复用 `src/utils/outline.ts:parseHeadings`,与 EditorOutline 同源,避免第二套 heading 解析逻辑漂移;空 query 列全集、有 query 走 `fuzzyScore` 子序列匹配(与 file / command 模式同款)。行视图按 `heading.level` 缩进(`paddingLeft = (level-1)rem`),与大纲面板视觉一致。**Enter 不直接跳,而是 emit `reveal-heading: { level, displayText }`**:跳转路径由 App.vue 按编辑器模式二选一,因为 source / WYSIWYG 定位机制完全不同,面板不该知道当前是哪种 backend。**source mode 精确**: `findHeadingRawOffset(content, level, displayText)` 逐行扫,跳过 fenced code block(` ``` ` / `~~~` 开闭计数,与 parseHeadings 的 `stripFencedCodeBlocks` 一致)防误匹配代码块里的 `#` 注释;命中后用 `stripFormatting(m[2])` 去掉 `**` / `_` / `` ` `` 等 inline formatting 再与 displayText 比;偏移即 CM6 pos(CM6 doc === raw markdown,offset 1:1),复用 FindReplaceBackend 的 `setSelection(offset, offset)` / `scrollMatchIntoView(offset)` / `focus()`(光标置偏移、不选区,语义是"跳到标题处")。**WYSIWYG 走 DOM 不走 raw→PM 映射**: `revealHeadingInDom(level, displayText)` 在 `.ProseMirror` 里 `querySelectorAll('h${level}')` + textContent 匹配 + scrollIntoView + 1500ms `outline-highlight` class(与 EditorOutline 跳转同款高亮)。这里**故意不做 raw 行号→PM pos 映射**:PM text node 计数与 raw per-line scan 在含 `code_block` / `image` / `mermaid` 时不一致(见 workspace search 同款坑),强映射会"结果已过期";WYSIWYG 直接 DOM 查询定位,语义是"跳到这个标题的视觉位置"。`revealHeadingInDom` 从 EditorOutline.vue 抽到 `src/utils/revealHeading.ts` 做去重,@ 模式与大纲面板共用同一条跳转路径。

- **统一命令面板 · line 模式(`:`):实时滚动 + 高亮目标行,跨模式会话恢复**(v0.6.2): 输入 `:` → 面板 emit `line-enter` → App.vue `onLineEnter` 记原模式 + 光标锚点(WYSIWYG 记 PM `captureAnchor`、源码记 CM6 光标 pos)**但不切源码**,只收起面板(`:` 模式隐藏列表 `v-if="mode !== 'line'"`,无行视图)+ 显示右侧内嵌 hint「输入要跳转的行号(从 1 到 N)」(N = `getLineCount(content)`)。**敲行号才切源码**: `line-preview: N` 进 `onLinePreview`,WYSIWYG 下置 `switched=true` + `pendingPreview=N` + `toggleSourceMode()`(行号是源码概念,无可靠 raw 行号→PM pos 映射,同 @ symbol / workspace search 坑);已在源码则直接 `applyLinePreview(N)`。**applyLinePreview** = `findLineOffset` 取行起始 raw offset(CM6 doc === raw markdown,offset == pos)+ `setSelection(offset, offset)` + `scrollMatchIntoView(offset)` + dispatch `cmLineHighlightEffect.of(N)`(**不 focus**,避免抢输入框);无效 / 越界 emit null → 清高亮。**CM6 行高亮**: `cmLineHighlightField`(StateField<number|null> 存行号)+ `cmLineHighlightDeco`(`EditorView.decorations.of` 读 field 出 `Decoration.line`,class `velo-cm-line-jump` 金色行底 + 左侧条,与 velo-find-match 同族);行号存 field、deco 用 `state.doc.line(n)` 取实时 from,自动跟住编辑(镜像 cmFocusModeTailDeco 的 of+读 field 模式)。**切源码抢焦**: CM6 挂载时 `SourceModeEditor.onMounted` 同步调 `view.focus()` 抢输入框焦点;面板 `watch(sourceMode)` 在 `:` 模式开时 `nextTick` 重聚焦输入框(跑在挂载之后赢过抢焦)。**切源码中的竞态**: `:` 后秒敲行号时 CM6 可能未挂载,`applyLinePreview` 返回 false → 行号存 `lineSession.pendingPreview`,跨模式同步 watch 在 CM6 挂载后(nextTick)补跳(跳过 anchor 恢复)。**Enter 确认**(留源码 + 当前行,清高亮)、**Esc / 离开 / 关闭 取消**(`onLineCancel`:`switched` 切过源码 → `pendingLineRestore` 置原 PM 锚点 + `toggleSourceMode` 切回,sync watch 用 `pendingLineRestore` 覆盖 anchor 恢复[否则会恢复到预览行的 CM6 光标];原源码且预览过 → `setSelection(cmPos)` 恢复,**不用 applyAnchor**[它 placeCursor 会 v.focus 抢输入框];只打了 `:` 未切未预览 → 无需恢复)。`findLineOffset` / `getLineText` / `getLineCount` 与 `findHeadingRawOffset` 同族(raw content → 行 offset / 行文本 / 行数),同居 `src/utils/revealHeading.ts`。

- **工作区搜索替换(v0.6.0)**: IO 与搜索逻辑拆开 —— `WorkspaceSearchPanel.vue` 只负责 UI(query / replacement / 命中行渲染),`utils/workspaceSearch.ts` 的 `applyWorkspaceReplace(hits, plan, dirtyPaths)` 是编辑器无关的纯函数 IO,App.vue 编排二者。流程:面板 emit `apply-replace` 携带 `{ hits, replacement, scope: 'one' | 'all' }` → App.vue 从 `documentStore.documents.values()` snapshot dirty tab 的 fullPath 集合(替换开始瞬间,避免 race)→ 调 `applyWorkspaceReplace` → 遍历 changedFiles 把磁盘已写的新内容同步到打开中的 clean tab(走 `documentStore.loadContentInto`,同步 content + lastSavedContent + 重建 watch) → 写 `replaceStatus` prop + `rerunToken++` 触发 panel 重跑搜索。**dirty tab 一律跳过**:用户编辑器里有未保存修改 → 替换读取的是磁盘基线,直接覆盖会毁掉用户编辑。全部替换完成后 `formatReplaceStatus` 把"已替换 X 处 / Y 个文件因有未保存修改被跳过 / Z 个文件读写失败"汇总到面板底部一次性 status,清空由用户后续搜索自然接管。**「替换」语义 = 当前选中条目所在文件的所有命中**:对齐编辑器内 Ctrl+H 但放宽到"按文件替换全部" —— 用户既然点了这条,大概率想清理整个文件;若想逐条改,先单文件打开再 Ctrl+H 即可。**「全部替换」= 当前所有结果命中文件**。**RegExp 复用 `replaceInText`**:regex 模式下保留 `$1`/`$2` 反向引用(caseSensitive / wholeWord / regex 选项与搜索阶段共享 `buildPattern`,语义一致)。**重跑触发用 token 计数器**:`rerunToken` 是单调递增整数,prop watcher 看到值变化就 `scheduleSearch` —— 比 `watch(() => initialQuery)` 更明确("有重跑信号"),且 initialQuery 不变不会触发。**未启用持久索引**:替换写盘后立即重跑搜索,fs:watch 也会触发 documentStore 的 `checkExternalChange`,两条路径在结果刷新上冗余但安全。
