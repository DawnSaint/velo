# Editor Architecture

> **本文件负责**: ProseMirror / CodeMirror 编辑器栈、markdownIO、语法实时转换、NodeView/Decoration、mermaid、shiki 与跨模式同步。
>
> **何时阅读**: 改 schema、markdownIO、ProseMirror 插件链、NodeView/Decoration、代码高亮、源代码模式、快捷键或新增 markdown 语法时。
>
> **先记住**:
> - `EditorInner.vue` 的 `allPlugins` 顺序是行为契约，改动需同步本文件。
> - mermaid / TOC 走 Decoration.widget，不走 NodeView；不要 dispatch setMeta 触发 mermaid widget rebuild。
> - shiki dark/light 翻面走 CSS；换主题 / 懒加载 lang 才触发受控 rebuild。
> - syntaxAutoFormat 的 apply 直接改框架传入的 `tr`，不要自己 dispatch。
> - markdownIO 双向改动必须补/跑 round-trip。
>
> **相关文件**: [架构入口](../ARCHITECTURE.md) / [查找替换](./find-replace.md) / [导出](./export.md)


## 禁令速查

- 不要 `dispatch setMeta` 触发 mermaid / shiki 重建；mermaid 直接写 widget DOM，shiki darkMode 纯 CSS。
- 不要用 `getLanguage()` 探活 shiki miss；用 `getLoadedLanguages()`。
- 不要把脚注编号写回 `attrs.label`。
- 快捷键不要在 `EditorInner.vue` 硬编码，走 `editor/shortcuts/bindings.ts`。
- `[TOC]` 回写 toMarkdown 不要用 text 节点。
- 不要清理 `getTokensCached` 这层 LRU。

## 设计要点

- **mermaid 走 Decoration.widget 不走 NodeView**: atom NodeView 的 outer dom `innerHTML` 变更会被 ProseMirror DOMObserver 当外部突变 → 全量 remount + 每字符 loader 闪烁;widget 的 `ignoreMutation` 默认忽略非 selection 突变。当前 `mermaid` 节点已废弃,```` ```mermaid ```` 改走 `code_block { language: 'mermaid' }`,由 `MermaidDecoration` 扫 code_block 渲染 SVG widget + 自管切换/删除/关闭按钮(默认 pre 隐藏,SVG `side:-1` 渲染在其前;点击 SVG 派发 setMeta 翻转 editNodePos,展开时 `queueMicrotask` 把光标放进 pre)。**坑**: plugin promise resolve 后不要 dispatch setMeta rebuild decorations,直接在 widget dom 上写 svg,否则 `WidgetType.eq` 失效 → 死循环;主题切换同理走 window listener 自改 dom + `spec.destroy` removeEventListener 防泄漏。PM 搜索命中隐藏的 mermaid 源码时,必须先走幂等展开 helper 再做 `TextSelection` / `coordsAtPos` / 滚动;不要直接 blind toggle,否则已展开块会被收起,或 Mermaid 自带 pending focus 抢走搜索选区
- **mermaid + codeHighlight 双 plugin 分工**: codeHighlight 负责所有 code_block 的 toolbar + 语法高亮;mermaid 走 MermaidDecoration 自管 SVG widget + 切换/删除/关闭按钮(codeHighlight 在 lang='mermaid' 上不挂 toolbar,避免同 pos 同 side 多 widget 冲突)
- **mermaid 语法高亮旁路 shiki**: shiki bundled mermaid grammar 薄(只输出按行纯文本 token),`codeHighlight` 对 `lang==='mermaid'` 走自写 `tokenizeMermaid`(6 类:keyword/direction/shape/edge/label/comment),颜色从当前代码块主题按 TextMate scope 提取 hex 写进 `--shiki-light/dark` 局部变量(同 shiki token 形态);主题切换/dark 切换两条路径同 shiki
- **shiki dual-theme 代码高亮**: `codeToTokensWithThemes` 返回 token 级双色,每 token inline `--shiki-light/dark` 变量,SCSS 按 `html.dark` 选。**darkMode toggle 纯 CSS 切色(零重渲);换主题(换 hex)才 rebuild**,由 App.vue watch 触发。首屏零闪烁:App.vue `codeBlockReady` 守门 PM mount;`state.init` 同步拿 cached highlighter
- **shiki 预扫 + 懒加载 lang**: 启动只装 doc 实际 lang ∪ 5 项 BASELINE(js/ts/py/bash/json);运行时 miss 用 `hl.getLoadedLanguages()` 探活(不能用 `getLanguage()`,miss 时 throw),异步追加 grammar 后**不直接 rebuild highlighter**,经 plugin 端 `setDecorationRebuildCallback` 钩子让 plugin 自己 rAF 节流 rebuild decorations(见下方“shiki 两条正交路径”)。**首次 miss 那帧无 token 是有意为之的"先骨架后着色"**
- **语法实时转换走 appendTransaction + dirty-range**(不走 InputRule 末尾匹配): `syntaxAutoFormat.ts` 从 `tr.mapping.maps` 提 dirty range → textblock 段首检测 + inline 正则扫描,黑名单(code_block/html_block/math_block)、code mark、link / image edit session 框架统一过滤。新增语法 = 写一个文件 + `syntax/index.ts` 注册一行。**坑**: block detector pattern 带 `^` 不带 `g`;inline 带带 `g` 不带 `^/$`;inline 扫描前 atom 用 NBSP 占位防穿透;语法 apply 直接改框架传入的 `tr`,不要自己 dispatch。**inline 扫描的 blockText 不能用 `doc.textBetween`**:它对"有 content 的非 text inline 节点"(footnote_reference `content:'text*'` / math_inline `content:'text*'`)会递进取 text content,输出的字符数 < 节点占的 doc 位置数(差 open+close tag 开销),match.index 映射回 doc 位置偏前 → replaceRangeWith 删错位置 / 删进节点边界。框架用自写的 `buildBlockText` 替代:text 节点追加 text content;inline 非 text 节点用 `\u0000` 占位(长度 = nodeSize,不递进 content);block 容器(doc/paragraph)下钻。黑名单检查从 `includes(' ')` 改成 `includes('\u0000')`
- **公式围栏守卫在 remark-math 前做文本预处理**: Velo 约定块级公式开头行必须只有 `$$`,同一行 `$$...$$` 继续按行内公式解析。`remark-math` 默认接受 `$$meta` 作为 flow math 开头,且 EOF 也能闭合,用户少写行尾 `$$` 时会把后续段落吞成一个 `math_block`;因此 pipeline 在 `remark-math` 前把“行首 `$$` 后有正文但本行没有闭合 `$$`”转义成普通文本。导出 HTML 复用同一守卫,避免编辑器与导出语义分叉
- **NodeView 隔离**: `ignoreMutation()` + `stopPropagation` 隔离 ProseMirror。**坑**:PM 的 `view.dom` 是 contentEditable 容器,所有 selection 统一由 PM 管理;在 NodeView 里嵌套 `contentEditable=true` 的子元素(sup / labelSpan)拿不到独立 focus —— 浏览器把 focus 给了子元素但 PM 的 selection 仍停在外层,Backspace/Delete 按 PM 的 selection(子元素外)处理 → "删错位置"。需要"光标进入、逐字符编辑"的 inline 节点(如 `footnote_reference` / `math_inline`)不要走 atom + contentEditable,改成 `content: 'text*'` 的非 atom 节点 + `contentDOM = dom`,让 PM 直接接管 text 编辑(selection 自然进入)。`footnote_reference` 的 label 作为 text content 而非 `attrs.label`,`math_inline` 的 source 同理(schema 早就 `content: 'text*'`,v0.5.9 起去 atom,见"math_inline 双模"),markdownIO 双向适配。`footnote_definition` 的 label(v0.5.8 起)同样拆成 `footnote_label` block 节点(`content: 'text*'`,作为 `footnote_definition` 的强制首子)而非 `attrs.label`,NodeView 不再自管 `labelSpan` 的 input/keydown:之前版本(<= v0.5.7)的 `<div class="footnote-label">` 是 NodeView 自造的、不在 contentDOM 子树内的元素,PM 看不到 → 点击 label 时 PM 默认把 selection 推进到最近的 content 子树 = 描述段 `<dd>` 前,Backspace/Delete 删错位置。改后与 `footnote_reference` 完全同范式,PM 接管 label 文本,光标自然进入 `<dt>` 内编辑。`FootnoteNodeViews.ts` 的 `currentLabel` 从 `node.firstChild.textContent` 读 label,`defs` 映射同步从 `firstChild.textContent` 算;`computeNumbering` 一处统一两份来源
- **NodeView 必须实现 `stopEvent`(math_block 踩坑)**:`isolateInputFromProseMirror` 的 `stopPropagation` 只能拦"事件从 textarea 冒泡"这一条路径,PM 的 `eventBelongsToView` 还会从 `event.target` 沿祖先链对每个有 `pmViewDesc` 的节点问 `stopEvent` —— 这是 PM 隔离 NodeView 子元素(嵌套 textarea / input)的**主要**机制。math_block 编辑态挂 textarea + preview,`stopEvent` 不实现 → 用户敲字符时 PM 走默认 `tr.insertText(text, from, to)`,math_block 当 NodeSelection 被替换 → "math 节点消失 / 输入框消失 / 光标消失"(`$$`+Enter 那条路径尤其明显,atom + NodeSelection 选中是默认 selection 形态)。**两道闸都要有**:inner 一侧 `isolateInputFromProseMirror` `stopPropagation`(目标在 textarea 时的快速路径)+ outer 一侧 NodeView `stopEvent` 返回 `true` 对 `beforeinput / input / keydown / paste / composition*` 等输入事件族,两闸互不依赖,任一就够拦住 PM。**math_inline 已去 atom**(v0.5.9 起,见下面"math_inline 双模"设计要点),不再挂自管 input/textarea,这条 stopEvent 机制对 inline 不再适用
- **图片源码编辑走 linkClick 同款 session 范式(非 math_block textarea 浮层)**: image 是 atom inline 节点,渲染 `<img>` 后无法改 src/alt/title。选中(NodeSelection)→ 右上角常驻 code-xml 按钮(`widgetIcons.ts`,CSS 按 `.selected` 显隐,尺寸沿用 `.velo-code-copy-btn`)→ 点按钮 `triggerImageEdit` 把 image 节点 `replaceWith` 成 `![alt](src "title")` 纯文本,默认选中 `()` 内的 src(改链接是最高频操作,无 title 时 src 正是 `()` 内全部);编辑期间图片不消失 —— Decoration.widget(`side:1`,渲染在源码文本下方)持图片预览,`key` 含当前源码文本 → 文本变 → 重建 widget → 实时跟随 src,源码残缺(不匹配 `parseImageSource`)→ 不挂 widget(图片隐藏,符合语法糖残缺不渲染)。用户像编辑普通文本一样改源码,`createImageEditPlugin` 的 session state(PluginKey 持有,生命周期跟 EditorState 一致)随 `tr.mapping` 平移 editFrom/editTo;光标移出范围 → `apply` 标 `pendingCommit` → `view.update` 触发 commit:`parseImageSource` 合法 → 重建 image 节点(NodeSelection 选中),残缺(删了 `!`/`(`)→ 保留为纯文本(Obsidian 降级),空值 → 删除;Escape → 重建点击前的原 image 节点(放弃编辑)。**与 linkClick 的关键差异**:linkClick 的 Escape 还原成 `[text](url)` 纯文本后靠 `syntaxAutoFormat` 重新转成渲染态 link mark;**image 没有实时键入转换**(syntax registry 无 image),纯文本 `![alt](src)` 不会自动变回 image,故 Escape 直接重建 image 节点而非插文本。session 状态机骨架(apply mapping + pendingCommit + view.update commit + Escape keymap)完全复用 linkClick。parse/serialize 纯函数在 `image/imageSource.ts`;imageNodeView 不持有编辑态 —— 替换成纯文本后本 NodeView 销毁,编辑期视觉层全靠预览 widget,commit 重建 image 后新 NodeView 创建、按钮重新出现。**proxyDomURL 复用**: image NodeView 与 edit 预览 widget 同一份 `resolveImageSrc`(EditorInner.vue),保证渲染态与编辑态预览解析一致。**坑(进编辑态不误判 dirty)**: trigger 事务(image→源码文本)挂 `SKIP_CONTENT_EMIT` meta(`editor/transactionMeta.ts`,useProseMirror 的 dispatchTransaction 见此 meta 跳过 `[alt](src)` 命中 link inline 正则,光标还在 session 内就被即时转成 link mark,`!` 成孤儿(有 title 时因 url 段含空格不命中正则,侥幸不触发,故 bug 只在无 title 时暴露)
- **图片段落尾随空行(隐藏 PM trailing break)**: image 是 inline atom 但 NodeView `display:block`,当图片是段落末子时,PM 的 `addTextblockHacks`(prosemirror-view `viewdesc.ts`)规则"末子非 `TextViewDesc` 即补 `<br class="ProseMirror-trailingBreak">`"命中,在图片下方撑出一条空行。**Chrome/Safari/WebView2 上还会额外补一个零宽 `<img class="ProseMirror-separator">`**(因末子 `contentEditable == "false"`,本 image NodeView span 即是),故 DOM 形如 `[image-span][separator][trailingBreak]` —— 相邻兄弟选择器须同时覆盖"span 直连 br"与"span 经 separator 连 br"两条路径(Firefox 不加 separator,只走第一条)。SCSS `.velo-image-inline + .ProseMirror-trailingBreak, .velo-image-inline + .ProseMirror-separator + .ProseMirror-trailingBreak { display:none }` 仅隐藏紧随图片之后的那条;空段自己的 trailing break(高度/光标来源)不动。separator 零宽不撑行,无需处理。PM 内部仍按 `matchesHack` 复用此 `<br>`,仅视觉隐藏,无 PM 层副作用 —— 不要删这条 SCSS,否则图片下方空行回归
- **选中图片时键入不生效(NodeSelection inert)**: image 是 `contenteditable=false` 的 inline atom,NodeSelection 的 focus 端在 Chrome/WebView2 上被渲染到下一个可编辑文本(图片下方段落首字符)—— 选区范围整段落在不可编辑内容上,浏览器把可视光标"借位"到最近可编辑位置(纯渲染产物,PM state 仍是 NodeSelection,`.selected` 蓝框 / 编辑按钮依故可见),用户键入会误 insert 到那里。两道闸挡住(都在 `imageEditPlugin.props`):`handleKeyDown` 吞可打印字符(`key.length===1` 且无 ctrl/meta/alt → 返回 true,PM `preventDefault` → 浏览器不发 beforeinput → 不 insert,主路径无闪烁);`handleTextInput` 兜底返回 true(覆盖 keypress 路径 / 浏览器已 insert 触发 readDOMChange —— 后者走 start-of-operation selection,`domchange.ts:9` 注释,此时 `state.selection` 仍是 NodeSelection,吞掉 dispatch 后 flush `updateState` 把 DOM 多余文本回滚)。Backspace/Delete/方向键/Enter/Escape(`key.length>1`)不吞,PM 默认删图/移动;ctrl/meta/alt 组合不吞,快捷键照常。**视觉光标**:SCSS `.velo-editor:has(.velo-image-inline.selected) { caret-color: transparent }` 选中态隐藏整编辑器文本光标(`:has()` WebView2 原生支持);取消选中 `.selected` 移除后自动恢复。源码编辑态 image 已替换成文本(无 `.velo-image-inline.selected`),光标正常显示
- **NodeView async render 的 stale-check 分工**:`renderKatex` 在 `await getKatex()` 前后各判一次,**但分工不同**:入口闸只判 `is-editing`(`$$`+Enter 自动进 math_block edit 这条路径需要);await 后的闸额外判 `!isConnected`(PM 已销毁 dom 的话放弃写入)。**坑**:入口闸不要判 `!isConnected` —— NodeView 工厂同步跑 showDisplay 时 PM 还没把 dom 挂到 view.dom,`isConnected === false` 是常态,入口闸 return 后整个 NodeView 寿命里 katex 都不再 render,用户感知"math 节点消失 / 切到源码模式再切回后空了"。math_inline 去 atom 后 showDisplay 不再有"覆盖刚挂好的 editor"的 race(contentDOM 由 PM 接管,没有 editor mount 时序),但 is-editing 入口闸对 math_block 的 autoEditMathBlocks 路径仍有意义 —— 保留
- **粘贴 text/plain 必须注册 `clipboardTextParser`**: ProseMirror 默认 plain-text fallback 把整段按 `\n+` 拆 `<p>` 再 `normalizeSiblings` 自动包 blockquote,产出错位 doc。`markdownPastePlugin` 走 fromMarkdown 输出**封闭 slice `(0,0)`**(非 `maxOpen`)走标准 "join 前后 paragraph" 路径把 blocks merge 进 doc 顶层

## 维护者注意点

- **脚注 label 是显示文本,无自动编号**: 扩展点是在 `FootnoteNumberPlugin.state` 加 `numbering: Map<label, number>`,**不要**把编号写回 label(丢语义,跟 GFM 不符)。`footnote_reference` 的 label 是 text content(schema `content: 'text*'`),`footnote_definition` 的 label 是 `attrs.label`
- **空 math 节点走占位不调 katex**:`MathNodeViews.ts` 的 `showDisplay` 在 `attrs.value`(block)/ `textContent`(inline)为空时改渲染 `.math-empty-placeholder`(虚线框 + 提示文字),不走 `renderKatex('' → ' ')` —— katex 输出高度趋近 0 的 `.katex-display`,WYSIWYG 里节点看起来"消失",源码模式却仍然能看到 `$$\n$$` 两行。math_block 占位 `pointer-events:none`,点击事件透传到 `.math-node` 上的 click listener → 重新进 `startEdit`。math_inline 占位同理,但 selection 一旦进入 math_inline 内(空节点)就走 selectionchange → data-mode="edit" → source 显示出来直接键入,不再需要 click → startEdit 的二段交互。`startEdit`(math_block)里 `setPreviewHtml(renderedHtml)` 也要按此短路:空节点捕获到的 `renderedHtml` 是占位 DOM,塞回 preview 会让 `querySelector('.math-empty-placeholder')` 重新命中 → 必须 `if (renderedHtml && node.attrs.value) editor.setPreviewHtml(renderedHtml)` 守卫。
- **shiki 两条正交路径**: darkMode toggle 纯 CSS 切色(零重渲,不要 dispatch setMeta);换主题 hex 变了才 rebuild,由 App.vue watch 触发。懒加载 lang(`ensureLanguage`)/主题(`ensureTheme`)只 append grammar/hex **不重建 highlighter**,走 plugin 端 `setDecorationRebuildCallback` 钩子让 plugin 自己决定 rebuild 时机;**不要 await getHighlighter 后立刻 dispatch setMeta**。CM6 源码模式同理:主题名镜像在 StateField,build 只读镜像(防 ensureTheme 未 resolve 期间全黑)
- **clipboard 统一走** `@tauri-apps/plugin-clipboard-manager` 的 `writeText`
- **code toolbar widget 用真盒子**,不能 `display:contents`: `display:block; height:22px`,`side:-1` 渲染在 `<pre>` 之前,用 `:has(+ pre:hover)` 联动 hover
- **快捷键 declarative registry**: 所有键位在 `editor/shortcuts/bindings.ts` 集中注册,**不**在 EditorInner.vue 硬编码。新加快捷键 = 新建 command 文件 + `bindings.ts` 加 1 行 `registerShortcut(...)`,不碰 EditorInner / registry.ts
- **inline syntax regex 必须自带 word boundary**,不依赖 registry 顺序防误识别: 开口 `(?<!\W)` / 闭口 `(?!\W)` 等挡前后导;inner 不含分隔符(如 strong inner `[^\n*]+?`)。例:`**33**` 必须被 strong 吃掉、`text==hi==` 不应被 highlight 误识别 —— 见 `syntax/inline/strong.ts` / `highlight.ts` 顶部注释
- **mark 语法闭合后必须 `removeStoredMark`**: `**bold**` / `*it*` / `==hl==` / `~~st~~` / `_em_` / `` `code` `` 的 apply(`delete → insertText → addMark`)后,光标停在 inner 末尾 = inclusive mark 右边界。这些 mark 的 `inclusive` 默认 true(schema 未设,与 `link` 的 `inclusive:false` 不同),且 apply 未设 storedMarks(=null),继续输入时 PM 回退到 `$from.marks()`(含该 mark)→ 继承粗体/高亮。修复:apply 末尾 `tr.removeStoredMark(markType)` 让 storedMarks=[] 覆盖继承(storedMarks 优先于 `$from.marks()`,故 inclusive 边界也能退出;与 Typora/Obsidian 一致)。**不要**改 `inclusive:false` 解决 —— 会破坏 Ctrl+B 连续输入(`markCommands` 的 `addStoredMark` 首字符消耗后,后续字符靠 inclusive 边界继承);`link` 能用 `inclusive:false` 因它不靠 Ctrl+B 连续输入;`code` mark `excludes:'_'` 独占无 Ctrl+` 命令,但仍走 `removeStoredMark` 保持一致。**这只覆盖"语法刚闭合那一笔"**;光标进入已有 mark 范围继续编辑由 `markSourceEditPlugin` 处理(见下条),两者互补不重叠
- **mark 源码编辑 session(Obsidian Live Preview 风格)**: `markSourceEditPlugin` 让光标进入 `**bold**` / `*it*` / `==hl==` / `~~st~~` / `` `code` `` 范围时,整段换成可编辑的 markdown 源码字符;移出光标 commit 还原成 mark。session 状态机(apply mapping bias +1/-1 + pendingCommit + `view().update` 触发 commit + Escape 还原)逐字照搬 `linkClick.ts` / `imageEditPlugin.ts`。
  - **触发用 `appendTransaction` 不是 handleClick**:光标进入即换源码。**保命守卫**:仅 batch 含 `selectionChanged && !docChanged` 的 tr 才触发 —— 键入 / IME / 粘贴是 `docChanged`(即便也移光标)不触发,保住 Ctrl+B 连续输入(`inclusive:true` 必须留,`addStoredMark` 首字符后靠边界继承)。commit tr 自身 `docChanged` 也不触发(双保险防重进)。仅 `resolve(head).marks()` 含目标 mark 时触发(内部 + inclusive 右边界);左边界(`head===markStart`,resolve 不含 mark)不进 —— typing 在左边界本就不继承,无需 session
  - **enter 守卫的 `isBlacklisted` 只挡 `code_block` / `math_block` 容器,不挡 `code` mark**:行内 `code` mark 本身是 session 目标,光标进入要换源码;`markCommands` 的 `code` mark 黑名单(Ctrl+B 在 code 内不切换)是另一回事,勿与 enter 守卫对齐。code mark `excludes:'_'` 独占,commit 不走 `applyMarkerWriteback`(只改 strong/emphasis),纯靠 `fromMarkdown` 重解析 `` `code` `` 还原 code mark
  - **commit 不调 `setSelection`,靠 `tr.mapping` 重映射光标**:用户已把光标移到 session 外,commit 的 delete+insert 让光标自然落在还原 mark 之外(右离开 `P-S+L >= editFrom+L+1` 过 mark 末尾;左离开 `<=editFrom-1` 在 mark 起点前,inclusive 左边界不含 mark)→ 不立即重进。**Escape 不同**:光标原本在源码内,mapping 会落回还原 mark 内 → 必须 `setSelection(editFrom)`(inclusive 左边界,不含目标 mark)
  - **`buildMarkSource` 自己拼保 `*`/`_`**:不能用 `toMarkdown` —— 它把 emphasis 恒输出 `_`、strong 恒 `**`,丢 `attrs.marker`。遍历 slice inline 节点按固定嵌套序(开:strong→emphasis→strike→highlight→code;闭反序)在 mark 转换处插 `markerText(mark)`(读 `attrs.marker`)。`**bold *italic***` → 两端 `**`+`*` 全显;`__bold__`/`_it_` 原样。`code` mark `excludes:'_'` 独占,不会与其他 mark 并存,`markerText` 恒返回单 backtick —— 多 backtick 代码(`` `` .. `` ``)进 session 降级为单 backtick(已知限制;源文件加载走 fromMarkdown 仍完整支持)
  - **commit marker 回写只改已存在 mark**:`fromMarkdown` 创建 strong/emphasis 用默认 `marker:'*'`,丢原始分隔符。commit 后只对**已带该 mark 的 text span** `removeMark`+`addMark(marker=detectMarker(source))` —— 不能对整段 addMark(会把破源码 / 改成别的 mark 类型时的 plain text 误加 strong)。`detectMarker` 用正则从源码检出 `*`/`_`
  - **`findMarkRange` 坑(inclusive 左边界)**:(a) char `[p,p+1]` 带 mark 当且仅当 `resolve(p+1).marks()` 含 mark,向前扫判 `resolve(start).marks()`(char 末位)而非 `resolve(start-1)`(左边界不含 mark 会漏首字符,delete 留孤儿)。(b) **块首专属**:`resolve(块首).marks()` 在 `nodeBefore` 为空时回退取 `nodeAfter` 的 marks(含本 mark),左扫用 `start>0` 会越过块开 token 落到块外(pos 0)→ `delete(0, markEnd)` 跨块边界,结构碎裂成 `**bold*` + 散落 `*`(commit 后变独立行 `*`)。左扫必须以块首内联起点 `resolve(pos).start(depth)` 为下界;右扫查 `resolve(end+1)` 不命中块首(nodeBefore 总存在),无需对称下界
  - **退避三处**:`syntaxAutoFormat.getActiveEditRanges` 返回全部活跃 session(link/image/mark)范围(见下条);`markCommands.forceStoredMarkOnly` 扩展含 markEditSession(session 内 Mod-b 只 `setStoredMark` 不插 `****`);link/image session 范围内不进(session 互斥,`buildMarkSource` 不处理 link 语法)
  - **多 session 并存必须全退避(翻倍坑)**:`getActiveEditRanges` 返回所有活跃 session 范围数组,`tryInlineSyntaxes` 用 `some(rangesIntersect)` 任一相交即跳过。**不能**早 return 优先一个 —— 多 session 并存时(例:link 编辑态展开期间 click strong,link session 尚未 commit、markSourceEdit 已 enter strong),若只退避 link 范围,strongSyntax 会把 mark session 的 `**bold**` 源码立即转回 mark → markSourceEdit session 经 mapping 倒置(editFrom > editTo)→ commit `textBetween`/`delete` 范围错乱 → insert 没对应 delete → **文本翻倍(每次 ×2)**。早期 `getActiveEditRange` 优先级 link > image > mark 早 return 踩此坑
  - **enter 事务挂 `SKIP_CONTENT_EMIT`**:瞬时视图切换(mark→源码文本)不回写,否则 `toMarkdown` 把源码 `**` 转义成 `\*\*` 与渲染态 mark 序列化不同 → 误判 dirty。commit / Escape 不挂(需回写把 content 同步到还原后的 mark)
  - 装入位置:`syntaxAutoFormatPlugin` **之前**(`EditorInner.vue` 的 `allPlugins`)—— appendTransaction 的 enter 让 `getActiveEditRanges` 在 pass 2 读到 session 自动退避。与 link/image escape keymap 同区;三者 Escape 各自 session 为 null 时 return false,顺序非关键
